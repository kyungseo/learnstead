# 문서 구조 표준

Learnstead 자료는 **어디서 시작하고, 무엇을 이해하거나 실행하며, 다음에 어디로 갈지** 같은 방식으로 안내합니다.
이 문서는 읽기 구조를, [그림 작성 원칙](VISUALS.md)은 시각 표현을, [발행 절차](PUBLISHING.md)는 공개 완료 조건을 소유합니다.
복사할 원본은 [템플릿](templates/README.md)에 있습니다.

## 적용 범위

가이드·튜토리얼·실습 폴더 바로 아래의 README, 장, 카드, 용어집, SOURCES, VALIDATION, CHANGELOG에 적용합니다.
코드·fixture·모델에 넣는 지시문·원문 인용·측정 결과 파일은 읽기 문서가 아니므로 탐색 블록을 삽입하지 않습니다.
자료의 순서와 파일 역할은 [문서 목록](content-index.json)에 명시합니다. 파일명·장 순서·기존 heading anchor를 변경할 때는 연결된 링크를 함께 확인합니다.

## 공통 페이지 골격

```text
H1 — 페이지 제목 하나
상단 탐색
대표 표지 — 자료 README에만
도입 — 독자가 만난 상황과 이번 페이지에서 얻을 결과
H2 — 의미 단위의 본문 섹션
H3 — 해당 섹션 안의 단계나 비교
확인할 결과·다음 행동 — 필요한 위치에
하단 구분선
하단 탐색 — 상단과 같은 목적지
```

- H1 바로 뒤에 상단 탐색을 둡니다. 표지는 탐색 아래에 둡니다.
- 탐색의 표시 제목과 경로는 문서 목록에서 생성합니다. 같은 블록을 상하단에 유지합니다.
- 장은 `이전 · 목차 · 다음`으로 이동합니다. 첫 장의 이전은 소개이며 마지막 장에는 이전과 목차만 둡니다. 다른 자료로 이어지는 연결은 본문에 보존합니다.
- 소개는 `학습 자료 목록 · 시작 · 검증 기록`, 지원 문서는 `자료 소개 · 학습 자료 목록`을 기본으로 합니다.
- 아래쪽에는 독립된 줄의 `---`를 한 번 두고 탐색을 이어 붙입니다. GitHub가 이를 굵은 가로 구분선으로 렌더합니다. 굵기를 CSS·이미지·밑줄 문자로 흉내 내지 않습니다.
- `##`와 `###` 앞뒤에는 빈 줄을 둡니다. 짧은 문단마다 구분선을 넣거나 모든 장에 같은 수의 섹션을 억지로 만들지 않습니다.
- 자동 관리 구간의 주석은 남겨 둡니다. 그 안은 `python3 tools/structure.py sync`로 갱신합니다.

## 자료 소개 README

| 순서 | 필수로 답할 질문 | 대표 섹션명 |
| --- | --- | --- |
| 도입 | 어떤 문제를 다루나? | 제목·도입 문단 |
| 대상·성과 | 누가 읽고 무엇을 할 수 있게 되나? | 누구를 위한 자료인가요? / 읽고 나면 할 수 있는 것 |
| 전제·경계 | 무엇이 필요하며 어디까지 다루나? | 시작하기 전에 / 범위와 검증 |
| 짧은 경로 | 전부 읽기 전에 어디부터 시작하나? | 가장 짧은 경로 |
| 전체 지도 | 어떤 순서로 읽거나 실행하나? | 목차 / 단계 지도 / 시나리오 지도 |
| 근거·연결 | 무엇을 확인했고 다음 자료는 무엇인가? | 검증과 출처 / 함께 사용할 자료 |

새 자료는 템플릿의 섹션명을 기본으로 사용합니다. 기존 자료의 제목·앵커가 이미 쓰이고 있으면 내용을 확인해 같은 역할로 유지할 수 있습니다. 이름만 통일하려고 기존 링크를 깨뜨리지 않습니다. 필수 질문의 답이 없으면 사실을 조사해 작성하며 빈 섹션이나 허위 실행 기록으로 채우지 않습니다.

소개 표지는 자료마다 하나이며 루트 카탈로그와 동일한 파일을 씁니다. 첫 개념 SVG는 소개 또는 첫 개념 장에 배치하고, 그림 앞에서 설명할 관계를 소개한 뒤 아래에서 핵심 판단을 풀어 씁니다. 표지와 도식의 목적은 [시각 기준](VISUALS.md)을 따릅니다.

## 유형에 따라 달라지는 본문

| 유형 | 핵심 전개 | 빠지면 안 되는 것 |
| --- | --- | --- |
| 가이드 | 상황 → 개념·관계 → 선택 기준 → 예 → 확인할 질문 | 조건과 한계, 주요 주장 출처, 실행 예의 성격 |
| 튜토리얼 | 결과 → 준비 → 실행 → 예상 결과 → 문제 해결 | 명령의 작업 위치·영향, 전체 경로 검증, 복구 |
| 실습 | 시나리오 → 입력 → 관찰 → 판정 → 초기화 | 고정 조건, 정상/실패 기준, 남긴 결과, 재실행 |
| 카드·용어집 | 사용법 → 항목·정의 → 원문 연결 | 작성/판단 예, 관련 장으로 돌아가는 링크 |

`AI에게 부탁할 말`은 AI와의 작업이 학습 목표일 때 넣습니다. 모든 장의 의무 문구가 아닙니다. 명령 블록에는 언어를 지정하고, 실행 전 필요한 안전 조건을 명령 뒤로 미루지 않습니다. 중요한 경고와 한계를 템플릿 정비 과정에서 삭제하거나 약화하지 않습니다.

## 근거 문서

- `SOURCES.md`: 출처, 확인일, 뒷받침하는 주장, 공식 문서/직접 실행/해석의 구분.
- `VALIDATION.md`: 실행 환경·버전·명령·기대와 실제 결과·실패·미검증 범위. 형식 변경을 재실행 검증처럼 날짜 갱신하지 않습니다.
- `CHANGELOG.md`: 공개 뒤 독자에게 영향을 주는 변화. 형식 변경도 적되 내부 작업 순서나 비공개 추적 번호는 싣지 않습니다.

## 기존 자료를 정비할 때

파일명·URL·heading anchor·코드·숫자·실행 기록·의미를 보존합니다. 자동 변경은 표시용 탐색, 표지 위치, 하단 구분선으로 한정합니다. 본문 의미·잘못된 정보는 별도 수정으로 명시하고 근거를 다시 확인합니다. 내장 구분선은 본문을 나누는 의미가 있으면 보존합니다.

## 확인 명령

```bash
python3 tools/structure.py check
python3 tools/validate.py --public
python3 -m unittest discover -s tools -p 'test_*.py'
git diff --check
```

구조 검사는 문서 목록, 탐색 목적지·상하 일치, footer, 대표 표지·첫 SVG 참조를 확인합니다. 사실성·설명 순서·그림의 의미와 판독성은 별도 검토합니다. GFM 파서로 강조 기호가 본문에 남지 않는지 확인하고, 실제 GitHub 첫 화면·소개·장·지원 문서를 확대/축소해 봅니다.
