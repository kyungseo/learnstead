# 검증 원칙

문장이 자연스럽다고 해서 사실이 검증된 것은 아닙니다. Learnstead는 문서 확인과 실제 실행을 분리하고, 재현에
필요한 환경과 결과를 각 자료의 `VALIDATION.md`에 남깁니다.

## 검증 등급

| 등급 | 필요한 기록 | 허용하는 표현 |
| --- | --- | --- |
| 실행 검증 | 날짜, OS·hardware, 도구·model version, 명령, 성공 조건과 실제 결과 | 기록한 환경과 범위에서 동작함 |
| 부분 검증 | 위 항목 + 실행하지 않은 단계 | 명시한 일부만 동작함 |
| 문서 확인 | 확인일, 공식 출처 URL, 확인한 claim | 공식 문서가 그렇게 설명함 |
| 미검증 | 미검증 범위와 독자 주의점 | 동작 여부를 확인하지 못함 |

다른 장비, version과 workload로 결과를 일반화하지 않습니다. 한 환경에서 성공했다는 사실은 그 환경의 evidence이지
모든 환경을 지원한다는 선언이 아닙니다.

## 명령을 검증할 때 남길 것

1. 처음 상태와 사전 준비
2. 실제로 실행한 명령
3. version과 model identifier
4. 성공을 판정한 출력 또는 동작
5. 실패했다면 오류와 원상복구 결과
6. 실행하지 않았거나 확인하지 못한 범위

API key, token, 내부 hostname과 개인 경로는 기록하지 않습니다. 파괴적이거나 비용을 일으키는 명령은 실행 전 영향과
복구 방법을 먼저 설명합니다.

## 공개 전 검사

- 내부 링크와 이미지 경로가 모두 존재하는가
- 공개하면 안 되는 식별자와 비밀값이 없는가
- `실행 검증` 표기에 실제 실행 기록이 연결되어 있는가
- 최신 정보가 공식 1차 출처와 직접 연결되어 있는가
- 명령의 사전 조건, 성공 판정과 복구가 함께 있는가
- SVG가 열리고 본문·그림·대체 텍스트의 주장이 일치하는가
- `미공개` 표기와 작성 중 placeholder가 남아 있지 않은가

저장소의 `tools/validate.py`는 구조·링크·공개 경계·SVG syntax를 빠르게 검사합니다. 실제 명령의 동작과 글의 의미는
자동 검사만으로 판정하지 않습니다.
