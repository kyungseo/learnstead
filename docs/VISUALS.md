# 그림 작성 원칙

## 원본과 파생본

구조도와 기술 인포그래픽은 SVG를 편집 가능한 원본으로 관리합니다. PNG가 필요하면 SVG에서 같은 크기와 배율 규칙으로
생성하고, PNG만 고쳐서 두 파일의 의미가 갈라지지 않게 합니다.

첫 화면의 대표 일러스트처럼 정확한 구조나 수치를 설명하지 않는 그림은 WebP 또는 PNG로 관리할 수 있습니다. 이 경우
작은 화면에서도 핵심 장면이 보이는지 확인하고, 파일 크기를 웹 문서에 맞게 줄이며, 같은 의미를 전달하는 대체 텍스트를
붙입니다. 대표 일러스트가 기술 도식의 역할을 대신하게 하지는 않습니다.

대표 일러스트에는 기존 카드와 같은 `Learnstead : 짧은 제목`을 그림 안에 넣습니다. 본문의 긴 H1을 그대로 반복하기보다
자료를 구분할 수 있는 짧은 제목을 쓰고, 3열 카드 크기로 줄였을 때도 읽히며 핵심 장면과 겹치지 않는지 확인합니다.

## 대표 일러스트의 공통 아이덴티티

루트 README의 카드와 각 자료 첫 화면에 쓰는 대표 일러스트는 Learnstead의 같은 시리즈로 보여야 합니다.
배경색의 기준은 [Git 가이드 표지](../guides/git-for-vibe-coders/assets/git-for-vibe-coders-hero.webp)입니다.
이 표지의 글자·그림이 없는 위쪽 종이 영역은 대략 `#FCF4EC`의 옅은 아이보리색입니다. 종이 질감의 미세한
편차는 두되 노란색 기운이나 가장자리 색 번짐이 강해지지 않도록 실제 참고 이미지와 비교합니다.

구도와 손그림 표현은 [바이브 코딩 가이드](../guides/vibe-coding-practice/assets/vibe-coding-practice-hero.webp)와
[Agent 오케스트레이션 가이드](../guides/agent-orchestration/assets/agent-orchestration-hero.webp)를 실제로 열어 비교합니다.

- 가로 약 16:9 화면에 기준 표지와 같은 옅은 아이보리색 종이 질감, 손으로 그린 검은 윤곽선과 부드러운 파스텔 색을 사용합니다.
- 위쪽에 큰 손글씨 느낌의 `Learnstead : 짧은 제목`을 놓고, 아래쪽에는 학습 주제를 보여 주는 하나의 장면을 둡니다.
- 민트·연보라·연노랑·연파랑 계열과 친근한 사물·인물·작은 로봇을 활용하되, 모든 표지에 같은 소품을 반복할 필요는 없습니다.
- 세부 설명을 빼곡히 적기보다 사물과 관계로 주제를 전달합니다. 회색 카드형 기술 도식을 대표 일러스트 대신 사용하지 않습니다.
- 웹 문서용 WebP 또는 PNG로 저장하고, 루트 README와 해당 자료 README가 같은 파일을 참조하게 합니다.
- 단독 확대 이미지뿐 아니라 기존 표지 옆의 3열 카드 크기로도 비교해 제목 판독성, 장면의 선명함, 비율과 색감을 확인합니다.

본문의 기술 도식은 편집 가능한 SVG로 관계를 정확하게 설명합니다. 대표 일러스트의 질감을 기술 도식 전체에
일괄 적용하지 않으며, 두 종류의 그림은 각각의 역할에 맞게 검증합니다.

## 그림도 본문과 같은 주장을 한다

- 본문에서 조건부로 설명한 내용을 그림에서 무조건적인 사실처럼 줄이지 않습니다.
- tokenizer나 실행 환경을 고정하지 않은 정확한 token 수처럼 근거 없는 숫자를 시각적으로 확정하지 않습니다.
- 본문, SVG의 `title`·`desc`, Markdown 대체 텍스트가 같은 범위와 제한을 전달해야 합니다.
- 제품 logo와 색상보다 정보의 관계와 읽는 순서를 우선합니다.

## 읽기 쉬운 기준

- 한국어가 줄바꿈돼도 label과 설명이 겹치지 않아야 합니다.
- 작은 화면에서 글자가 지나치게 작아지는 경우 한 장을 여러 장으로 나눕니다.
- 색만으로 상태를 구분하지 않고 label, 선 모양이나 위치를 함께 사용합니다.
- 밝은 배경과 어두운 배경에서 핵심 text와 line의 contrast를 확인합니다.
- 장식보다 단계, 계층, 비교와 선택 경로가 먼저 보여야 합니다.

## 검증

SVG source는 XML parsing과 전용 lint를 통과해야 합니다. 대표 그림은 2배 PNG로 render해 잘림, 겹침, 정렬, CJK
font fallback과 축소 판독성을 눈으로 확인합니다. 그림을 수정한 뒤에는 body와 alt text도 다시 대조합니다.
