# DELEGATION-CARD — 일을 나눠 맡기기 전과 후

## 먼저 정할 것

직접 처리로 충분하면 그대로 진행합니다. 위임하려면 **무엇을 개선하려는지와 결과를 어떻게 확인할지** 먼저 정합니다. 읽기 부담에는 subagent 위임, 독립 과제의 시간에는 병렬 실행, 검토 관점에는 기준을 명시한 재검토나 별도 컨텍스트를 검토합니다. 효과는 각자 측정합니다.

## 무엇을 나누고 누가 조정하나

| 선택 | 역할 | 확인 |
| --- | --- | --- |
| subagent | 메인이 정해진 일을 맡기고 결과를 받음 | 초기 이력·권한·결과 전달 범위 |
| worktree의 병렬 세션 | 별도 작업 폴더에서 실행, 사람이 조정 | branch·쓰기 범위·통합 담당자 |
| agent teams | lead와 teammate가 직접 조율 | 실험 기능, 승인 주체·비용. 이 가이드는 문서만 확인 |
| dynamic workflow | 스크립트가 여러 실행을 조정 | 반복할 절차·종료 조건. 이 가이드는 문서만 확인 |

worktree는 폴더 분리이고 subagent는 위임 단위입니다. 둘을 함께 사용할 수 있습니다.

## 위임 요청의 네 항목

1. **대상:** 파일·함수·작업 범위. 이전 대화를 받는지는 도구와 호출 방식에 따라 다릅니다.
2. **완료 조건:** 기대 동작과 확인 방법. “테스트 통과”만으로 기능 완료를 대신하지 않습니다.
3. **제약:** 쓰기 범위와 건드리지 않을 파일·설정·커밋.
4. **보고 형식:** 근거 위치·결과·미완료 항목. 메인은 원문과 최종 결론을 대조합니다.

## 병렬 편집 전

- 별도 branch·worktree, 겹치지 않는 쓰기 범위, 최종 통합 담당자를 정합니다. 범위를 나누기 어려우면 순차로 처리합니다.
- Claude Code의 새 worktree는 기본적으로 원격 default branch에서 시작합니다. 현재 HEAD의 커밋이 필요하면 `worktree.baseRef: "head"`를 확인합니다. 일반적인 tracked 파일의 미커밋 변경은 따라가지 않습니다.
- 동시성은 실행 구간으로, 시간 절감은 순차 대조로 확인합니다. 통합·검사가 빠진 시간을 전체 완료 시간과 비교하지 않습니다.

## 검토와 종료

- 검사 결과를 먼저 확인하고, 검토자에게 README·요구사항 등 판단 기준을 지정합니다.
- 결함 검토와 개선 제안을 구분합니다. 골든셋 밖 지적은 오탐과 같지 않습니다.
- 중요한 변경의 최종 승인 주체를 정합니다. 로그가 담당자 지정이나 승인을 대신하지 않습니다.
- 예산·동시 수·검토 라운드 상한을 정합니다. 프롬프트 지침과 도구가 강제하는 제한은 구분합니다.

## 결과를 읽는 법

파일 5개 실습에서는 위임 후 메인 마지막 컨텍스트가 3~7% 줄고 전체 입력량은 늘었습니다. 병렬 조건의 실행 시간은 순차의 0.6~0.65배였지만 통합과 품질도 별도로 확인해야 합니다. 같은 세션과 새 컨텍스트의 규격 위반 발견 횟수에는 차이가 없었습니다. 작은 과제·도구당 3회의 관측이며, 고정 선택 기준은 아닙니다.
