# 06. 지시문 크기 vs 준수율 — 실측

> 이전 ← [`05-budget-and-compaction.md`](05-budget-and-compaction.md) · 다음 → [`07-what-not-to-put-in.md`](07-what-not-to-put-in.md)

## 이 장에서 답하는 질문

- 지시문이 길어지면 정말 덜 지켜지는가
- 같은 규칙을 어디에 두느냐가 준수율을 얼마나 바꾸는가
- 두 도구는 어디서 갈리는가

## 1. 설계

- **과제** 고정: 작은 Python 패키지에 `slugify(text)` 함수 추가 + 테스트 + CHANGELOG. 두 도구 모두 비-대화형(`claude -p`, `codex exec -s workspace-write`).
- **규칙 5개** 고정, 기계 판정: 새 `.py` 첫 줄 `# owner: platform-team` · 모든 함수에 한국어 docstring · 모든 함수에 타입 힌트 · 테스트 파일 위치와 `test_slugify_<경우>` 이름 · CHANGELOG `[Unreleased]`에 한 줄. 여기서 "모든 함수"는 `check.py`의 기준상 테스트 함수도 포함합니다.
- **기존 코드는 규칙을 따르지 않는다**(라운드 2). 그래서 규칙은 코드에서 추론할 수 없고 지시문에서만 옵니다.
- **변형 6개** × 3회 × 2도구 = 36회. 판정은 `check.py`가 5점 만점으로.

## 3. 읽기

### 코드에 없는 규칙은 지시문 없이 지켜지지 않았다

당연해 보이지만 라운드 1과 대조하면 의미가 분명해집니다. 라운드 1(기존 코드가 규칙을 따름)에서는 V0도 15/15였습니다. **모델은 코드에서 관례를 읽습니다.** 지시문이 필요한 것은 코드에 없는 관례입니다.

### 길이의 영향은 도구마다 달랐다

Codex는 V1 15 → V2 10으로 떨어졌습니다. 놓친 것은 한국어 docstring(3회 모두)과 타입 힌트(2회)였습니다. 176줄 속에 흩어진 규칙 둘을 놓쳤고 **희석(dilution)이** 관측됐습니다. Claude Code는 V1 11 = V2 11로 차이가 없었습니다. 다만 V1에서 이미 4점을 놓치고 있어서, 같은 항목(테스트 함수의 docstring·타입 힌트)을 계속 놓친 것이 길이 효과를 가렸을 수 있습니다 [해석]. 한 도구에서만 관측된 효과이므로 "긴 지시문은 덜 지켜진다"는 **경향으로만** 읽습니다. 문서의 200줄 권고와 방향은 같습니다.

### 애매한 규칙은 좁게 읽힌다

Claude Code가 V1에서 놓친 4점은 전부 **테스트 함수였다**. "모든 함수에 한국어 docstring·타입 힌트"를 구현 함수에만 적용했습니다. Codex는 V1에서 테스트 함수까지 적용했습니다. 같은 문장을 두 모델이 다르게 읽은 것입니다. 실습 후 규칙을 "테스트 함수를 포함한 모든 함수"로 고쳤다면 Claude의 점수가 올랐을 가능성이 크다 [해석]. 준수율 실험에서 가장 먼저 의심할 것은 길이가 아니라 **문장의 모호함이다**.

### 이번 실험에서는 pointer가 import보다 낮았다

Claude Code에서는 pointer 9 < import 13이었습니다. pointer 3회 모두 모델은 `docs/RULES.md`를 읽었다고 답했는데도 점수가 낮았습니다. 읽은 파일은 "참고"로, 지시문에 들어온 텍스트는 "지시"로 취급되는 차이로 보입니다 [해석]. Codex는 둘 다 14였습니다. `@`가 문자 그대로라 둘 다 pointer였지만 잘 읽었습니다.

### 조건부 로드는 도구의 기제를 써야 한다

Claude Code의 경로 규칙(V4)은 13으로 import와 같았습니다. `.py` 파일을 읽는 순간 규칙이 들어왔습니다. Codex의 중첩 `src/AGENTS.md`는 6이었습니다. cwd가 루트라 자동 로드되지 않았고, 모델이 파일로 읽고도(3회 모두 transcript에 읽는 줄이 있음) 규칙 셋을 놓쳤습니다. **같은 "하위 디렉터리 지시문"이 한 도구에서는 조건부 로드이고 다른 도구에서는 그냥 파일입니다.**

## 4. 실험의 한계

- 3회씩 실행했습니다. 점수 2~3점 차이는 잡음일 수 있습니다. 0 vs 15, 15 vs 6 같은 큰 차이만 결론으로 삼았습니다.
- 과제 하나, 규칙 5개, 두 모델. 다른 과제·규칙·모델에서 수치는 다릅니다.
- Claude Code 실행은 이 장비의 `permissions.defaultMode: "auto"`에서 진행했습니다(편집을 묻지 않음). 다른 설정에서는 턴 수가 다를 수 있습니다.
- V2는 176줄입니다. 200줄을 넘는 파일에서 효과가 더 클지는 확인하지 않았습니다.

## 5. 이 실험을 내 프로젝트에서 반복하려면

실습 [`labs/instruction-budget`](../../labs/instruction-budget/README.md)의 fixture를 그대로 쓰되 규칙 5개를 내 관례로 바꾸고 `check.py`를 맞춥니다. 핵심은 **기계 판정과** **기존 코드가 규칙을 따르지 않는 상태입니다.** 둘 중 하나가 빠지면 라운드 1처럼 모든 변형이 만점이 되어 아무것도 배우지 못합니다.

## 이 장을 끝내면

- 지시문 크기·위치·형태가 준수율에 미친 영향을 수치로 말할 수 있습니다.
- 준수율이 낮을 때 길이보다 문장의 모호함을 먼저 의심합니다.
- 조건부 로드를 도구의 기제로만 구현합니다.
