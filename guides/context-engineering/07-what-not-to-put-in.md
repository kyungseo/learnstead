# 07. 무엇을 넣지 말 것인가

> 이전 ← [`06-size-vs-adherence.md`](06-size-vs-adherence.md) · 다음 → [`08-glossary.md`](08-glossary.md)

## 이 장에서 답하는 질문

- 지시문·memory·컨텍스트에 넣으면 손해인 것은 무엇인가
- 각각 어디로 보내야 하는가

## 1. 넣지 말 것 — 목록

| 넣지 말 것 | 왜 | 대신 |
| --- | --- | --- |
| **코드에서 읽어 낼 수 있는 것** — 디렉터리 구조, 의존성 목록, 아키텍처 개요 | 모델이 코드에서 추론한다(실습 라운드 1: 지시문 없이 15/15). 바뀌면 지시문이 거짓말을 한다 | 없애거나 `/doctor` 제안대로 잘라 낸다. 필요하면 "어디를 보라"만 |
| **여러 단계 절차** | 매 세션 로드되고 관련 없는 작업에서 주의를 끈다 | skill |
| **코드 일부에만 해당하는 규칙** | 매 세션 로드 | 경로 조건 규칙(Claude) / skill(Codex) |
| **서로 충돌하는 규칙** | "임의로 하나를 고른다" [문서 확인] | 하나만 남긴다. 여러 파일(루트·하위·규칙·memory)을 함께 본다 |
| **애매한 규칙** — "깔끔하게", "적절히" | 좁게 또는 제각각 읽힌다(실습: "모든 함수" → 구현 함수만) | 검증 가능한 문장. 예외와 포함 범위를 명시 |
| **강제해야 하는 것** — "commit 전 lint" | 지시문은 강제가 아니다 | hook · CI · lint |
| **Secret·절대 경로·개인 식별자** | git에 들어가고 남의 장비에서 깨진다 | 환경 변수, `CLAUDE.local.md`, gitignore된 로컬 설정 |
| **대화로만 준 세션 규칙** | 압축 뒤 사라질 수 있다 | 지시문 파일에 적는다 |
| **팀 규칙을 개인 memory에** | 다른 사람·도구는 모르고, 지시문만으로 동작이 유도되는지 검증 불가 | 저장소의 지시문·skill |
| **참고 자료 전문** | 항상 로드 비용. 읽을지도 모르는 것 | pointer + 읽을 시점 |
| **"자세한 건 X를 봐"만** | 조건부 로드가 아니다(실습: pointer 9 < import 13) | import(Claude) 또는 도구의 조건부 기제 |
| **긴 도구 출력·파일 전문을 대화에 그대로** | 컨텍스트를 채우고 압축을 앞당긴다 | 범위 지정 읽기, 요약 옵션, 서브에이전트 |

## 2. 지시문 감사 순서

한 분기에 한 번쯤 지시문 파일들을 열고:

1. **코드로 대체 가능한 줄을** 지운다. "src/api에 핸들러가 있다" 같은 것.
2. **절차를** skill로 옮기고 한 줄 라우팅만 남긴다.
3. **특정 경로 규칙을** 경로 조건 규칙으로 옮긴다.
4. **충돌을** 찾는다. 루트·하위·규칙·사용자 파일·memory를 함께 펼쳐 놓고.
5. **애매한 문장을** 검증 가능한 문장으로 바꾼다. "모든 X"에는 포함 범위를 적는다.
6. 남은 것이 200줄을 넘으면 4단계로 돌아간다.
7. `/context`로 실제 로드 크기를 확인한다.

## 3. 반대로 — 꼭 넣어야 하는데 빠지기 쉬운 것

- **하지 말 것.** 코드에는 "하지 않은 것"이 안 보입니다. `reset --hard` 금지, 특정 디렉터리 편집 금지.
- **왜.** 규칙의 이유가 있으면 모델이 경계 사례에서 옳게 판단합니다.
- **명령.** 테스트·빌드·실행 명령은 매번 찾으면 탐색 비용이다(실습: 지시문 없을 때 턴 수 증가).
- **아직 코드가 따르지 않는 새 관례.** 기존 코드에서 추론하면 옛 관례를 따릅니다.

## 이 장을 끝내면

- 넣지 말아야 할 12가지와 각각의 대체 자리를 설명할 수 있습니다.
- 지시문 감사를 7단계로 돌릴 수 있습니다.
- 빠지기 쉬운 네 가지(하지 말 것·왜·명령·새 관례)를 확인할 수 있습니다.
