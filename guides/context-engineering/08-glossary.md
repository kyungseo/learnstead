# 08. 용어집

등장 순서대로 배열했습니다.

| 용어 | 뜻 | 장 |
| --- | --- | --- |
| **컨텍스트 창** | 모델이 한 번의 추론에서 보는 토큰 전체. system prompt·지시문·도구 정의·대화·도구 결과 | 01 |
| **Context Engineering** | 추론 시점에 모델이 보는 토큰 집합을 고르고, 가져오고, 유지하는 일. 프롬프트 작성은 그 일부 | 01 |
| **주의 예산 / context rot** | 컨텍스트가 길수록 그 안의 정보를 정확히 꺼내는 능력이 떨어지는 현상 | 01 |
| **진입 지시문** | 세션 시작 시 항상 로드되는 파일. `CLAUDE.md`·`AGENTS.md`·`GEMINI.md` | 02 |
| **계층·연결(concatenation)** | 조직·사용자·프로젝트·하위 파일을 덮어쓰지 않고 순서대로 이어 붙이는 방식 | 02 |
| **`@import`** | Claude Code에서 다른 파일을 시작 시 함께 로드하는 문법. 5단계 재귀 | 02, 03 |
| **`project_doc_max_bytes`** | Codex의 지시문 합계 상한(기본 32 KiB) | 02 |
| **경로 조건 규칙** | `.claude/rules/*.md`의 `paths:` glob. 매칭 파일을 읽을 때 로드 | 03 |
| **하위 디렉터리 지시문** | Claude: 그 디렉터리 파일을 읽을 때 로드 / Codex: cwd가 그 아래일 때만 | 03 |
| **pointer** | "X를 보라"는 문장. 조건부 로드가 아니라 모델의 판단 | 03 |
| **local memory** | 에이전트가 작업에서 배운 내용을 사용자 장비에 저장하는 기능. Claude Code는 auto memory를 제공하고 Codex는 opt-in local memory를 지원 | 04 |
| **structured note-taking** | 에이전트가 진행 상황을 컨텍스트 밖 파일에 적고 리셋 뒤 이어 가는 기법 | 04 |
| **작업 문서** | 사람과 모델이 함께 쓰는, 저장소가 소유하는 상태·결정 기록 | 04 |
| **just-in-time retrieval** | 전부 미리 넣지 않고 식별자만 두고 필요할 때 도구로 가져오는 방식 | 05 |
| **compaction (압축)** | 컨텍스트가 찰 때 대화를 요약으로 바꾸는 동작. 층마다 생존 방식이 다름 | 05 |
| **재주입** | 압축 후 디스크에서 다시 읽어 넣는 것(루트 지시문·memory·계획) | 05 |
| **서브에이전트** | 별도 컨텍스트에서 일하고 요약만 돌려주는 위임 | 05 |
| **희석(dilution)** | 긴 지시문 속에서 개별 규칙이 덜 지켜지는 현상. 이 가이드에서는 한 과제·한 도구(Codex)의 3회 실행에서 관측한 경향 | 06 |
| **기계 판정** | 규칙 준수를 스크립트로 채점하는 것. 실험의 전제 | 06 |
| **추론 가능한 관례** | 기존 코드에서 모델이 읽어 낼 수 있는 규칙. 지시문에 적을 필요가 없는 것 | 01, 07 |
