# 09. 다른 사람에게 공개해도 될까?

스터디 앱을 만들어 신청 정보를 저장할 수 있게 됐다고 해 보겠습니다. 이제 다른 사람에게 앱 주소를 알려 줘도 될까요? 그 전에 사용자마다 볼 수 있는 데이터와 사고 후 복구 방법을 확인해야 합니다. 이 장에서는 앞에서 배운 내용을 바탕으로 공개 전 확인할 사항을 정리합니다.

아직 앱이 없다면 앞으로 무엇을 준비할지 읽어 두세요. 앱이 있다면 개발용 사본이나 연습 환경에서 아래 항목을 확인해 보세요.

결과물은 **근거가 적힌 데이터 관리 카드 한 장입니다**. 모든 항목에 ‘완료’를 쓰는 것이 목적은 아닙니다. 확인한 범위와 남은 책임이 드러나야 합니다.

## 화면에서 데이터까지 한 번 따라가기

가상 사용자 A가 모임을 보고 신청한 뒤 자신의 신청을 취소하는 정상 경로를 확인합니다. 다음에는 B와 비로그인 상태로 같은 데이터에 접근해 봅니다. 브라우저 화면과 실제 API 결과, 저장된 데이터가 일치하는지 비교합니다.

새로고침과 서버 재시작 뒤 값이 남는지, 앱이 개발 DB와 운영 DB 중 어디를 가리키는지도 확인합니다. 로컬 실습에서 동작했더라도 실제로 배포할 환경에서는 DB 연결·권한·저장 유지 여부를 다시 확인해야 합니다.

## 공개 판단에 필요한 근거

| 질문 | 남길 근거 | 멈추고 해결할 예 |
| --- | --- | --- |
| 올바른 DB를 쓰나? | 비밀값 없는 환경 식별, 연결 경로 | 개발 화면이 운영 DB를 가리킴 |
| 데이터 규칙을 지키나? | 정상·중복·없는 대상·동시 요청 결과 | 중복이나 정원 초과 기록이 남음 |
| 권한이 맞나? | A·B·비로그인별 실제 응답과 변경 여부 | 다른 사람의 신청을 변경 가능 |
| 비밀이 노출되지 않나? | 브라우저 산출물과 설정 분류 확인 | 높은 권한의 키가 브라우저에 포함 |
| 변경 후 옛 데이터가 남나? | 기존 데이터에 migration 적용 결과 | 새 DB에서만 실행해 봄 |
| 잃으면 되살릴 수 있나? | 별도 복원 결과, 백업 범위 | 백업 생성만 확인하고 복원은 모름 |

이것은 특정 앱의 보안 인증서나 운영 승인서가 아닙니다. 규모, 개인정보, 결제, 조직 정책에 따라 추가 검토가 필요합니다. 실제로 수집하지 않아도 되는 데이터는 애초에 저장하지 않는 편이 관리할 문제를 줄입니다.

## AI가 완료했다고 말할 때

“테스트 전부 통과”의 대상이 무엇인지 읽습니다. 화면 테스트만인지, 관리자 권한으로 DB를 확인한 것인지, 일반 사용자 요청으로 거절까지 확인했는지 구분합니다. 자동 검사는 작성한 조건을 검사합니다. 작성하지 않은 조건의 안전까지 증명하지 않습니다.

실습에 포함된 실패는 고정 입력으로 관찰하기 위해 만든 교육용 사례입니다. 실제 AI 도구가 어떤 비율로 실수한다는 통계가 아닙니다. 자신이 사용하는 AI가 생성한 코드는 별도로 읽고 실행해야 합니다.

## 다음 사람에게 전달할 내용

[데이터 관리 카드](DATA-CARD.md)를 복사해 앱과 함께 보관합니다. 어떤 데이터를 어디에 저장하는지, 누가 관리하는지, 변경·백업·복원 방법이 무엇인지 기록합니다. 비밀번호는 카드에 붙이지 않고 허가된 비밀 관리 수단의 위치만 설명합니다.

불필요한 실제 데이터를 테스트 코드·스크린샷·로그·AI 대화에 넣지 않습니다. 오류를 설명할 때는 구조를 유지한 가상 데이터로 재현할 수 있는지 먼저 봅니다. 서비스 중단이나 계정 이전 때 데이터를 내보내고 삭제할 책임도 지정합니다.

<a id="ai에게-부탁할-말"></a>

## AI에게 지시할 프롬프트

> 공개 준비 결과를 데이터 관리 카드로 정리해 줘. 실제 실행한 환경·명령·결과와 문서만 읽은 항목을 구분해 줘. A, B, 비로그인 권한 시험, 기존 데이터 migration, 별도 복원을 포함하고 미확인 항목은 완료로 표시하지 마. 비밀값과 실제 사용자 데이터는 제외해 줘.

다음에는 [용어집](10-glossary.md)에서 낯선 말을 다시 확인하거나, [신청 앱 튜토리얼](../../tutorials/study-signup-db/README.md)로 넘어가 직접 만들어 보세요. 앱이 이미 있다면 [DB 안전 실습](../../labs/database-safety/README.md)의 관찰 기준을 연습 환경에서 적용할 수 있습니다.
