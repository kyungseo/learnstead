# 데이터 관리 카드

[가이드 목차](README.md) · [공개 전 확인](09-ready-to-share.md)

자신의 앱에 맞춰 복사해 사용하는 기록 양식입니다. 아래의 빈칸은 독자가 채우는 항목이며 예제의 검증 결과가 아닙니다. 비밀번호·키·실제 사용자 데이터는 적지 않습니다.

## 앱과 저장소

| 항목 | 내 앱의 기록 |
| --- | --- |
| 앱의 목적·관리자 | |
| 저장하는 데이터와 수집 이유 | |
| 저장하지 않아도 되는 데이터 | |
| DBMS·버전·운영 서비스 | |
| 개발·운영 환경을 구분하는 방법 | |
| 브라우저·서버·DB의 요청 경로 | |
| 파일 본체 저장소와 DB 메타데이터 관계 | |
| 새로고침·재시작·다른 기기에서 유지되는 것 | |

## 구조와 권한

| 항목 | 내 앱의 기록 |
| --- | --- |
| 주요 테이블·문서와 ID | |
| 필수값·중복 금지·참조 규칙 | |
| 삭제가 다른 기록에 미치는 영향 | |
| 정상 사용자에게 허용하는 작업 | |
| 다른 사용자·비로그인에게 거절하는 작업 | |
| 공개용 설정과 서버 전용 비밀의 구분 | |
| 실제 사용자 권한으로 확인한 날짜·환경·결과 | |

## 변경과 복구

| 항목 | 내 앱의 기록 |
| --- | --- |
| migration 파일 위치와 적용 방법 | |
| 기존 데이터가 있는 상태의 변경 검증 | |
| 중복·동시 요청·중간 실패의 판정 결과 | |
| 백업 위치·주기·보관 기간·읽기 권한 | |
| 백업에 포함되지 않는 데이터·파일 | |
| 허용 가능한 데이터 손실 시간·복구 시간 | |
| 별도 대상에 복원한 날짜·환경·결과 | |
| 코드와 DB를 함께 되돌리는 방법 | |
| 데이터 내보내기·서비스 종료 시 삭제 방법 | |
| 비용 확인 방법·알림과 강제 제한의 차이 | |
| 미확인 항목·다음 확인 담당자 | |

## 결과를 적는 예

‘권한 확인 완료’보다 ‘연습 환경에서 A가 B의 신청을 수정한 요청은 변경 0건, B의 원본은 유지’처럼 적습니다. 백업은 생성 날짜와 복원 성공 날짜를 구분합니다. 이 문장 자체는 작성 예이며 실제 관측 기록이 아닙니다.
