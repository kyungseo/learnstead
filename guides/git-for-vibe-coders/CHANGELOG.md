# 변경 기록

**AI로 코딩하는 사람을 위한 Git의** 독자 대상 내용과 검증 범위 변화를 기록합니다.

## 2026-08-27 — Learnstead 공개판

- AI 코딩의 핵심 흐름을 **Save → Inspect → Isolate → Share로** 재구성하고, 10분 안에 첫 commit을 만드는 진입 경로를
  추가했습니다.
- branch와 worktree의 관계를 "작업의 갈래"와 "갈래를 펼친 별도 작업 폴더"로 구분하고, 생성·병렬 작업·merge·정리까지
  실제 실행한 새 장을 추가했습니다.
- AI 세션마다 worktree와 branch를 하나씩 배정하고, scope·검증·merge 판단을 분리하는 실전 흐름을 보강했습니다.
- `restore`·`pull`·`push`·`stash` 등을 무조건 안전하다고 분류하지 않고, 상태만 읽는 명령·전제 확인이 필요한 변경·멈춰야 할
  파괴적 명령으로 신호등을 다시 구성했습니다.
- 기존 Private github.com 저장소의 첫 Public 전환과 공개 저장소의 version release 전에 확인할 범위를 추가하고,
  `github-release-guide`의 Assess·Guided·승인 단위·사후 검증 경계를 소개했습니다.
- 개념을 중복하던 ASCII·Mermaid 도식을 제거하고, AI–Git 전체 흐름과 worktree 도식 2종을 SVG로 추가했습니다.
- 초심자에게 하나의 전략을 "정답"으로 단정하거나 AI가 의도를 "모른다"고 표현하던 문장을 전수 검토해 조건과 결정 주체가
  드러나도록 고쳤습니다.
- 기존 14종과 신규 3종, 총 17종 SVG를 lint하고 2배 PNG로 렌더링해 시각적으로 확인했습니다.

## 2026-08-23 — 초판

- "Git을 직접 잘 다룰 필요는 없다. 개념만 알면 AI에게 정확히 지시할 수 있다"를 전제로, 모든 개념·시나리오에 「AI에게 이렇게
  말하세요」 상자를 붙였습니다.
- 버전 관리의 개념과 CVS·SVN·Git 세 세대, Git과 GitHub의 차이를 설명했습니다.
- macOS(터미널·zsh·Xcode 명령줄 도구)와 Windows(Git for Windows·Git Bash·경로 표기)의 준비 과정을 나눠 담았습니다.
- 작업 폴더·스테이징·로컬 저장소·원격 네 공간으로 add·commit·push·pull·stash를 설명했습니다.
- 커밋의 구조와 상황별 되돌리기(restore·revert)를 담고, `reset --hard`가 커밋되지 않은 작업을 영구 삭제한다는 것을 실제로
  실행해 확인했습니다.
- 브랜치와 트렁크 기반 전략을 권장 전략으로 제시하고, 병합 충돌을 유도해 표시와 해결 3단계를 실제 출력으로 담았습니다.
- 커밋 메시지 작성법, GitHub 올리기와 PR을 다뤘습니다.
- 혼자 만들 때 여섯 시나리오와 올리고 나눌 때 네 시나리오를 상황 중심으로 구성했습니다.
- AI 작업 지시문 20여 개와, 위험 명령을 초록·노랑·빨강으로 나눈 신호등을 제공했습니다.
- 로컬에서 실행 가능한 모든 시나리오(총 4개 실습 저장소)를 macOS·Git 2.50.1에서 실행 검증하고, 검증 중 발견한 것(stash pop
  충돌, Fast-forward의 `-m` 무시, `revert`에 `-q` 없음)을 본문에 반영했습니다.
