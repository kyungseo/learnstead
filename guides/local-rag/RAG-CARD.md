# 내 RAG 구성 카드

답이 나왔다는 사실만이 아니라 **무엇을 색인했는지(Index), 무엇이 검색돼 프롬프트에 들어갔는지(Ask), 근거가 답을
뒷받침하는지(Prove)를** 한 장에 남기는 기록 양식입니다. 청킹·검색·모델을 바꿀 때마다 아래 template을 복사해 사용하세요.

← [가이드 README](README.md) · 다음 → [01 생태계 지도](01-ecosystem-map.md)

## 기록 원칙

- 문서 원문, 개인정보, 내부 주소와 비밀값은 적지 않습니다. 문서는 **개수·종류·출처 유형만** 적습니다.
- "잘 됨" 대신 조각 수, 모델 이름과 차원, top-k, 점수 하한, 질문과 근거 판정 결과를 적습니다.
- 구성을 바꿨을 때는 **한 번에 하나만** 바꾸고 같은 질문 묶음으로 다시 재서 비교합니다.
- 공개 자료로만 확인한 내용과 직접 실행한 결과를 구분합니다.

## 복사해서 쓰는 template

```md
# RAG 구성 카드 — <구성 이름>

## 목적

- 답하려는 질문의 종류:
- 성공 기준:

## Index — 무엇을 색인했는가

- 문서: (개수 · 형식 · 출처 유형)
- 파싱 방법:
- 청킹: (전략 · 크기 · 겹침 · 조각 수)
- embedding model과 차원:
- 저장소: (리스트 / Chroma / pgvector / …)
- 그래프: (없음 / 추출 모델 · 노드 수 · 엣지 수)
- 색인 일시와 소요 시간:

## Ask — 무엇이 검색돼 들어갔는가

- 검색 방식: (dense / bm25 / hybrid) · reranker:
- top-k · 점수 하한:
- 프롬프트 규칙: (근거만 / 없으면 모른다 / 번호 인용)
- 생성 모델 · temperature · max_tokens:
- runtime과 적용된 context 창:

## Prove — 근거가 답을 뒷받침하는가

- 질문 묶음: (개수 · 그중 "문서에 없는 질문" 개수)
- 근거 판정: 통과 n / 실패 n
- 실패 유형별: ① 검색 누락 n · ② 잘못된 조각 n · ②′ 불완전 답변 n · ③ 관련 없는 문서 n · ③′ 단어 겹침 n · ④ 근거 없는 답변 n
- 질문 성공률(`question success@k`) / 필수 구절 재현율(`phrase recall@k`) (이 실습의 구절 기반 골든셋을 쓴다면):
- 확인일:

## 한계와 다음 조치

- 아직 확인하지 않은 것:
- 이번에 바꾼 한 가지와 그 결과:
- 다음에 바꿔 볼 한 가지:
```

## 가장 짧은 예시

아래는 튜토리얼·실습 구성을 적은 예시입니다. Apple M4 Pro·24GB Mac, Ollama 0.33.0에서 관찰한 값입니다. `[실행 검증 · 2026-08-30]`

| 단계 | 기록 |
| --- | --- |
| Index | Markdown 4편(가상 규정) / 단락 청킹, 조각 17개 / bge-m3 1,024차원 / Python 리스트 |
| Ask | dense · top-k 3 · 하한 없음 / 규칙 3종 / gemma3:4b · temperature 0 |
| Prove | 질문 4건 근거 판정 4/4 통과 · 실패 재현: ① ✗(점수 격차만) ② ○ ③ ○ ④ △(단어 겹침에서 발현) |
| 경계 | 문서 4편의 실습 구성이며 규모·권한·갱신은 다루지 않음 |

세부 판정 방법은 [실습](../../labs/why-rag-fails/README.md), 평가를 숫자로 바꾸는 방법은 [09 §4](09-personal-vs-enterprise.md)와 [실습 ④](../../labs/why-rag-fails/04-golden-set.md)를
참고하세요.
