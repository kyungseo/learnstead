| --- | --- |
| **다섯 줄** | 만들기 전에 적는 최소 기준 — 누가·무엇을·어떤 순서로·뭘 보면 성공·이번엔 안 함 ([01 §2](01-decide-first.md)) |

## 2. AI 코딩 용어

| 용어 | 뜻 |
| --- | --- |
| **바이브 코딩 (vibe coding)** | AI에게 자연어로 지시하며 결과를 보고 빠르게 프로그램을 만드는 방식. 2025년 Andrej Karpathy가 재미로 만드는 일회성 프로젝트의 작업 모습을 설명하며 널리 알려짐 ([README](README.md)) |
| **Agent (에이전트)** | 목표를 받아 파일을 읽고 수정하거나 명령과 도구를 실행하며 여러 단계를 진행할 수 있는 AI 시스템 |
| **Agentic Engineering** | AI Agent가 구현의 많은 부분을 맡더라도 사람이 목표·범위·감독·검증·품질을 책임지는 작업 방식. Karpathy가 2026년 바이브 코딩과 구분하기 위해 제안한 표현 ([README](README.md)) |
| **컨텍스트 창 (context window)** | AI가 한 번에 읽을 수 있는 양. 차면 도구가 앞부분을 요약하거나 잘라냄 ([07 §1](07-context-limits.md)) |
| **프롬프트 (prompt)** | AI에게 보내는 요청문 |
| **환각 (hallucination)** | AI가 없는 것을 있는 것처럼 말하는 것. 코드에서는 없는 함수·라이브러리를 쓰는 형태로 나타남 |
| **의존성 (dependency)** | 프로젝트가 쓰는 외부 라이브러리 ([08 §1⑤](08-before-sharing.md)) |
| **환경 변수 / .env** | Secret을 코드 밖에 두는 방법 ([02 §3](02-safety-net.md)) |
| **기술 stack (tech stack)** | 앱을 만드는 데 함께 쓰는 언어·framework·database·도구의 조합 ([00 §2](00-big-picture.md)) |
| **Frontend** | 사용자가 보는 화면을 만들고 입력을 받는 부분 ([00 §2](00-big-picture.md)) |
| **Backend** | 업무 규칙·권한·외부 서비스 호출처럼 화면 뒤의 처리를 맡는 부분 ([00 §2](00-big-picture.md)) |
| **API** | Frontend와 Backend처럼 서로 다른 프로그램이 정해진 방식으로 요청과 응답을 주고받는 접점 ([00 §2](00-big-picture.md)) |
| **Database** | 앱의 데이터를 저장하고 조건에 맞게 조회하는 시스템 ([00 §2](00-big-picture.md)) |
| **hosting / 배포** | 만든 앱을 다른 사람이 접속할 수 있는 서버 환경에 올려 실행하는 일 ([00 §3](00-big-picture.md)) |
| **BaaS (Backend as a Service)** | database·로그인·파일 저장 등 Backend의 공통 기능을 관리형 서비스로 제공하는 방식 ([00 §3](00-big-picture.md)) |
| **harness** | 계획·규칙·검사 도구를 묶어 AI가 같은 작업 절차를 반복하도록 돕는 안전장치 ([00 §3](00-big-picture.md)) |
| **platform lock-in** | 특정 서비스의 기능에 의존해 다른 환경으로 옮길 때 코드나 데이터를 크게 바꿔야 하는 상태 ([00 §4](00-big-picture.md)) |

## 3. 함께 쓰는 Git 용어

자세한 것은 [Git 가이드 용어집](../git-for-vibe-coders/13-glossary.md)에 있습니다.

| 용어 | 뜻 |
| --- | --- |
| **커밋 (commit)** | 되돌릴 수 있는 저장 지점 |
| **`.gitignore`** | Git이 무시할 파일 목록. Secret 파일을 여기에 등록 |
| **`git restore 파일`** | 그 파일만 마지막 커밋 상태로 (안전) |
| **`git revert`** | 커밋을 취소하는 새 커밋을 만듦 (안전) |
| **`git reset --hard`** ⛔ | 커밋 안 된 작업을 영구 삭제 (위험) |
| **README** | 프로젝트 설명 파일. 실행 방법과 한계를 적음 ([08 §4](08-before-sharing.md)) |
| **해시 (hash)** | 커밋마다 붙는 고유 번호(예: `e4f5g6h`). `git log`에서 봄 |
| **라이브러리 (library)** | 남이 만들어 둔 코드 묶음. AI가 자주 추가하며, 각각 라이선스가 있음 ([08 §1⑤](08-before-sharing.md)) |
| **절대 경로 (absolute path)** | `/Users/내이름/...`처럼 내 컴퓨터에서만 맞는 파일 위치. 코드에 있으면 남의 컴퓨터에서 안 됨 ([08 §1②](08-before-sharing.md)) |

## 4. 혼동하기 쉬운 쌍

| 쌍 | 차이 |
| --- | --- |
| **"AI가 됐다고 함" vs "내가 확인함"** | 전자는 확인이 아닙니다 ([05](05-verify-without-reading.md)) |
| **바이브 코딩 vs Agentic Engineering** | 흐름을 따라 빠르게 실험하기 ↔ Agent를 활용하되 사람이 검증과 품질을 책임지기 |
| **되는 것 vs 다 된 것** | 눌러서 동작 ↔ 저장·정리·공유 준비까지 |
| **실패 vs 막힘** | 한 번 안 됨 ↔ 두 번 이상 같은 자리 |
| **저장(Ctrl+S) vs 커밋** | 파일을 바꿈 ↔ 되돌릴 지점을 남김 |
| **대화 vs 프로젝트** | 대화는 사라져도 됨 ↔ 파일과 커밋이 자산 ([07 §4](07-context-limits.md)) |
| **오늘 멈춤 vs 방법 접기** | 쉬었다 같은 방법으로 ↔ 방법을 바꿈 ([09 §1](09-when-to-stop.md)) |
| **"일단 되니까" vs "안전하니까"** | 동작 ↔ 검증. 돈·개인정보·인증에서는 다릅니다 ([09 §1③](09-when-to-stop.md)) |
| **요청이 크다 vs 목표가 크다** | 쪼개면 됨 ↔ 다섯 줄을 다시 봐야 함 |
