# 01. 저장 — 껐다 켜도 남는가

[← 목차](README.md) · [전체 목차](README.md) · [02 규칙 →](02-constraints.md)

화면에서 한 줄이 보이는 상태와 다음 실행에도 남는 상태를 구분합니다. **계정 없이 가능한 SQLite 비교를 먼저 하고, 신청 앱에서도 다시 읽어 확인합니다.**

## 시나리오와 질문

메모장 앱을 AI에게 만들게 했다고 가정합시다. “저장했습니다”가 보이는데 프로그램을 닫았다 열면 목록이 없습니다. 버튼 문구만 보고는 저장 위치를 알 수 없습니다.

이 실습의 코드는 같은 모양의 데이터를 SQLite 메모리 DB와 파일 DB에 넣습니다. 의도적으로 고정한 교육용 사례이며, 특정 AI가 실제로 만든 실패를 측정한 결과가 아닙니다.

SQLite도 `:memory:`로 열면 연결이 끝날 때 사라지는 메모리 DB를 사용할 수 있습니다. 제품 이름만 보고 지속성을 단정하지 말고 **어떤 방식으로 열고 어디에 저장했는지** 확인해야 합니다. `[문서 확인 · 2026-09-13]` [SQLite 메모리 DB](https://www.sqlite.org/inmemorydb.html)

## 먼저 실행하기

이 실습의 폴더 `labs/database-safety`에서 실행합니다. Python 3가 필요하며 외부 Python 패키지나 클라우드 계정은 필요 없습니다.

```bash
python3 code/sqlite_lab.py
```

스크립트는 자기 임시 폴더에서 데이터를 만들고 종료하며 정리합니다. 자신의 기존 DB 파일을 대상으로 지정하지 않습니다. 실행 전 메모리와 파일 각각에 대해 “연결을 닫고 새로 열면 값이 남을까?”를 예상해 보세요.

## 관찰과 판정

| 조건 | 예상 | 판정에 필요한 증거 |
| --- | --- | --- |
| 메모리 DB에 넣고 같은 연결에서 조회 | 값이 보임 | 입력한 값과 조회한 값이 일치 |
| 메모리 DB 연결을 닫고 새 연결 | 이전 데이터 없음 | 이전 연결의 데이터가 사라짐 |
| 파일 DB에 넣고 연결을 닫은 뒤 같은 파일 열기 | 값이 남음 | 다시 연 파일에서 같은 행 조회 |

메모리 DB에서 사라지는 것은 이 설정의 정상 동작입니다. 영구 저장이 필요한 앱에 그 설정을 사용했다면 요구사항과 맞지 않는 선택입니다. “SQLite가 저장을 못 한다”는 결론을 내리지 않습니다.

## 내 파일에 넣고 다시 읽기

이번에는 자동 비교와 별도로 **눈에 보이는 파일을 남깁니다.** 아래는 `labs/database-safety` 폴더에서 처음 실행하는 경로입니다. 이미 `practice.sqlite`를 만들었다면 보존할 데이터가 없는 연습 파일인지 확인하고 아래 초기화 절차로 비운 뒤 시작하세요.

```bash
python3 code/sqlite_lab.py add --db practice.sqlite --title '데이터 이야기'
```

`저장 완료:` 뒤에 실제 파일 경로가 나오고 다음 내용이 표시됩니다.

```json
[
  {
    "id": 1,
    "title": "데이터 이야기"
  }
]
```

이제 첫 명령은 끝났습니다. 같은 터미널에서 다른 명령으로 파일을 다시 엽니다.

```bash
python3 code/sqlite_lab.py list --db practice.sqlite
```

같은 한 행이 나오면 별도의 프로그램 실행이 같은 DB 파일의 데이터를 읽은 것입니다. Finder에서도 현재 폴더에 `practice.sqlite`가 생겼는지 확인할 수 있습니다. 이 파일은 글자 문서가 아니므로 텍스트 편집기로 내용을 고치지 마세요.

같은 제목을 한 번 더 추가해 보세요.

```bash
python3 code/sqlite_lab.py add --db practice.sqlite --title '데이터 이야기'
python3 code/sqlite_lab.py list --db practice.sqlite
```

첫 명령은 `저장 거절: UNIQUE constraint failed: books.title`로 끝나고, 두 번째 명령에서는 여전히 한 행만 보여야 합니다. 이 예제는 제목을 고유하게 정한 작은 독서 기록입니다. 실제 도서 서비스에서 같은 제목의 책을 금지해야 한다는 설계 권고는 아닙니다.

이제 다음 명령은 **직접 만든 연습 파일의 `books` 행을 모두 지웁니다.** 결과를 기록한 뒤 실행하세요.

```bash
python3 code/sqlite_lab.py reset --db practice.sqlite --confirm-local-reset
python3 code/sqlite_lab.py list --db practice.sqlite
```

`초기화 완료: books 0행`과 `[]`가 보이면 초기화 성공입니다. 파일 자체는 남습니다. 이 파일이 필요 없다면 Finder에서 자신이 만든 `practice.sqlite`만 삭제할 수 있습니다. 다른 DB 파일을 대상으로 경로를 바꾸지 마세요.

## 신청 앱에서 한 번 더

[튜토리얼](../../tutorials/study-signup-db/README.md)을 따라 앱을 실행했다면 A로 신청한 뒤 아래를 확인합니다.

1. 신청한 모임을 기록합니다.
2. 브라우저를 새로고침합니다.
3. 이 예제는 로그인 세션을 메모리에만 보관하므로 다시 로그인합니다.
4. 같은 모임이 내 신청 목록에 남아 있는지 확인합니다.
5. 웹 서버를 멈췄다가 다시 실행한 뒤에도 같은 계정으로 확인합니다.

로그인이 풀렸다는 사실과 신청 내역이 사라졌다는 사실을 구분하세요. 다른 계정으로 접속했거나 다른 DB 주소에 연결한 경우도 먼저 확인합니다.

## 다음 행동 정하기

> “신청 직후에는 보이지만 다시 실행하면 사라져. 저장 위치와 앱이 다시 읽는 DB 주소를 확인해 줘. 로그인 상태가 초기화된 것인지, 실제 신청 행이 사라진 것인지 분리해서 설명해 줘.”

클라우드 배포 후에도 로컬 파일이 같은 방식으로 유지된다고 가정하지 않습니다. 호스팅의 파일 저장 방식은 별도 조건이고, 이 실습은 그 환경을 검증하지 않습니다.

## 초기화

옵션 없는 자동 비교의 임시 DB는 실행이 끝나면 정리됩니다. 직접 만든 `practice.sqlite`는 남으므로 위의 `reset`으로 행을 비우거나 파일 자체를 정리합니다. 자동 비교를 다시 실행하면 처음부터 같은 조건으로 비교합니다. 신청 앱의 데이터를 비우려면 [튜토리얼의 초기화](../../tutorials/study-signup-db/01-prepare.md)를 사용합니다. **DB 초기화는 지속성 확인을 끝낸 뒤** 실행하세요. 초기화 때문에 사라진 데이터를 저장 실패로 판단하면 안 됩니다.
