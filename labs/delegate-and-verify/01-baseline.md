# 01. 기준선 — 한 세션이 하는 만큼

> [목차](README.md) · [다음: 02. 위임 →](02-delegate.md)

## 목표

작업 분담의 효과를 비교할 기준값을 만듭니다. 한 세션이 검토와 구현을 직접 처리할 때의 입력 토큰, 총 경과 시간, 결함 위치 일치 수를 두 도구에서 3회씩 기록합니다.

## 1. 돌리기

```bash
./scripts/batch.sh main 3 s01-review-direct s01-task-direct
```

`s01-review-direct`는 `prompts/review-correctness.md`(규격과 다른 결함만 JSON으로)를 직접 수행합니다. Claude Code는 `--disallowedTools Agent`, Codex는 `agents.enabled=false`로 위임 도구를 끕니다. Codex의 `--sandbox read-only`는 파일 쓰기 제한이며, 위임 금지와는 별개입니다. `s01-task-direct`는 과제 A(`parse_memo` 추가 + 테스트)를 직접 구현합니다.

## 2. 채점

```bash
python3 scripts/score.py --tsv runs/main/*-s01-*
```

열: `main_in_total`(메인 입력 토큰, 캐시 포함) · `sub_in_total`(위임분, 여기서는 0) · `hits`(미리 정한 결함 위치 3개와 일치하는 지적 수) · `fp`(골든셋 밖 지적) · `wall_s`(총 경과 시간, 초) · `tests`(테스트 결과).

## 작성 환경의 실제 결과

| 도구 | 과제 | 메인 컨텍스트(끝) | 메인 누적 입력 | 출력 | 벽시계 | 결과 |
| --- | --- | --- | --- | --- | --- | --- |
| Claude Code | 검토 | 25,143 | 69,457 (46,535~69,587) | 722 | 17.1초 | 3/3 위치 일치·골든셋 밖 지적 0 |
| Claude Code | 과제 A | 24,225 | 69,010 | 1,721 | 34.1초 | 테스트 통과 3/3 |
| Codex | 검토 | 25,291 | 119,121 | 604 | 22.9초 | 3/3 위치 일치·골든셋 밖 지적 0 |
| Codex | 과제 A | 25,527 | 194,516 | 2,282 | 86.7초 | 테스트 통과 3/3 |

Codex 검토 벽시계는 첫 배치 값(18.6·22.9·28.5초)입니다. 재실행은 네트워크 시간 초과가 겹쳐 110초 안팎으로 부풀었습니다.

- 두 도구 모두 골든셋의 결함 위치 세 곳과 일치하는 지적을 냈습니다. 위치 일치 점수만으로 설명의 정확성까지 확정하지 않으며, 원문을 골든셋의 원인·영향과 대조합니다. 이후 단계는 이 직접 검토를 기준선으로 비교합니다.
- 입력량·시간·캐시 상태는 회차마다 달라질 수 있습니다. 중앙값을 쓰되 호출 횟수와 실행 조건도 함께 확인합니다. 캐시를 포함한 입력 총량의 차이를 캐시 상태 하나로 설명하지 않습니다.

## 흔한 실패 · 복구

| 증상 | 원인 | 복구 |
| --- | --- | --- |
| `tests` 열이 `None` | 실행이 중간에 끊겨 `tests.txt`가 없음 | `runs/main/<실행>/stderr.txt` 확인 후 해당 회차만 `run-*.sh`로 재실행 |
| Codex가 `Reading additional input from stdin...` 후 멈춤 | stdin이 열려 있음 | 스크립트는 `</dev/null`을 붙입니다. 직접 실행할 때도 붙이세요 |
| 적중 0, `parsed: false` | 답이 JSON 형식이 아님 | `answer_excerpt`를 보고 프롬프트의 출력 형식 문장을 유지 |
