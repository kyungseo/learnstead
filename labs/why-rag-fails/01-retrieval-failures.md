# 01 — 검색·청킹 실패: ① 검색 누락 · ② 잘못된 조각 · ②′ 불완전 답변 · ③ 관련 없는 문서 · ③′ 단어 겹침

답이 틀렸을 때 가장 먼저 볼 곳은 **근거 목록입니다.** 이 문서의 시나리오는 전부 "근거 목록에 정답이 없거나 반만 있는" 경우이고,
마지막 ③′은 그 상태가 생성 실패로 번지는 장면입니다.

← [README](README.md) · 다음 → [02 생성 실패와 진단표](02-generation-failure.md)

> **검증 상태:** 모든 명령을 Apple M4 Pro·24GB Mac, Ollama 0.33.0, `bge-m3`·`gemma3:4b`에서 실행했습니다. `[실행 검증 · 2026-08-30]`
> ①은 재현되지 않았고, ③′은 예상보다 나쁘게 나왔습니다. 각 시나리오에 그대로 적었습니다.

---

## 시나리오 ① — 검색 누락: 정답이 있는데 못 찾는다

**재현:** 자산 코드로 묻습니다. 문서에는 `EQ-2291`이 두 번 나옵니다.

```bash
cd labs
python3 rag_minimal.py "EQ-2291 장비는 어떻게 처리되나요?" --top-k 2
```

**관찰:** 근거 상위 2개에 `장비-규정 › 4. 교체 주기`(우선 교체 대상)가 없거나 낮은 순위로 밀려나면 실패 ①입니다. dense
검색은 "EQ-2291"을 의미가 흐린 기호로 보기 쉽기 때문입니다([가이드 04 §1](../../guides/local-rag/04-embeddings-and-vector-search.md)).

**작성 환경의 실제 결과 — 재현되지 않았습니다.** bge-m3는 `교체 주기`를 1위(0.52), `장비 반납`을 2위(0.46)로 찾았고 답도
맞았습니다. 조각이 17개뿐이고 "EQ-2291"이 조각 본문에 글자 그대로 들어 있어서입니다. 그런데 **점수를 보세요** — 1위 0.52에
무관한 조각들이 0.4대로 바짝 붙어 있습니다. 같은 질문을 BM25로 돌리면 1위 16.2, 2위 15.3(둘 다 EQ-2291이 있는 조각), 3위 2.0으로
정답과 무관 조각의 **격차가 8배입니다.** 조각이 수천 개가 되면 0.5 근처의 무관한 조각이 수십 개 생기고, 그때 dense는 밀립니다.
재현되지 않은 것이 "문제가 없다"는 뜻이 아니라 "아직 작아서 안 보인다"는 뜻입니다. `[실행 검증 · 2026-08-30]`

**고치기:** 키워드 검색을 섞습니다.

```bash
python3 rag_minimal.py "EQ-2291 장비는 어떻게 처리되나요?" --top-k 2 --search bm25
python3 rag_minimal.py "EQ-2291 장비는 어떻게 처리되나요?" --top-k 2 --search hybrid
```

**★ 판정:** dense·bm25·hybrid 세 경로 모두 `교체 주기`가 1위였고 답이 "4년 교체 대상·2022년 이전 우선 교체"를 근거와
일치하게 답했습니다. `[실행 검증 · 2026-08-30]` 내 환경에서 dense가 밀렸다면 hybrid에서 복구되는지 확인하고, 밀리지 않았다면
**점수 격차를** 기록해 두세요 — 그것이 규모가 커졌을 때의 예고입니다.

| 원인 부품 | 검색 (dense의 구조적 한계) |
| --- | --- |
| 처방 | hybrid(BM25+RRF) — [가이드 05 §2](../../guides/local-rag/05-chunking-and-retrieval-quality.md) |
| 실무에서의 신호 | 코드·제품명·조항 번호 질문에서만 유독 틀림 |

## 시나리오 ② — 잘못된 조각: 답이 두 조각에 걸쳐 잘렸다

**재현:** 휴가-규정 §3은 단락 청킹으로 #15(규칙 문장: 3월 말까지)와 #16(한도 목록: 5일·10일)으로 나뉘어 있습니다. top-k를 1로
줄여 한 조각만 넣습니다.

```bash
python3 rag_minimal.py "관리자는 연차를 며칠까지 이월할 수 있나요?" --top-k 1
```

**관찰:** 근거가 #15 하나뿐이면 "3월 말까지"는 답하지만 "10일"은 답하지 못하거나, 더 나쁘게는 **없는 숫자를 채워 넣습니다.**
반대로 #16만 들어오면 "10일"은 답하지만 "언제까지"는 모릅니다. 어느 쪽이든 **정답이 한 조각에 온전히 없는** 상태입니다.

**작성 환경의 실제 결과:** #16(한도 목록)이 1위(0.71)로 들어왔고 답은 "관리자(팀장 이상)는 연차를 최대 10일까지 이월할 수
있습니다 [1]" — 기한(3월 말)은 빠졌습니다. **반만 맞는 답이** 그대로 재현됐습니다. `[실행 검증 · 2026-08-30]`

더 극단적으로는 문장 중간을 끊어 봅니다.

```bash
python3 rag_minimal.py --chunk fixed:60 --show | head -40
python3 rag_minimal.py "관리자는 연차를 며칠까지 이월할 수 있나요?" --chunk fixed:60 --top-k 2
```

작성 환경에서는 60자 조각 #30(0.71)·#28(0.65)이 들어왔고 답은 역시 "최대 10일"뿐이었습니다. 조각을 잘게 자를수록 정답이 한
조각에 들어갈 확률은 떨어집니다 — [04 골든셋](04-golden-set.md)에서 이 효과를 숫자로 봅니다. `[실행 검증 · 2026-08-30]`

**고치기:** 조각 경계를 바꾸거나(한도 목록을 앞 단락에 붙임), top-k를 늘려 두 조각이 함께 들어오게 합니다. 근본 처방은
**부모-자식 청킹**(작은 조각으로 찾고 절 전체를 넣기)입니다.

```bash
python3 rag_minimal.py "관리자는 연차를 며칠까지 이월할 수 있나요?" --top-k 3
```

**★ 판정:** 근거에 #15·#16이 모두 들어오고 답이 "3월 말까지, 최대 10일"을 한 문장에 담으면 고쳐진 것입니다.

| 원인 부품 | 청킹 |
| --- | --- |
| 처방 | 구조 경계 존중, 부모-자식, 표·목록은 머리글과 함께 — [가이드 05 §1](../../guides/local-rag/05-chunking-and-retrieval-quality.md) |
| 실무에서의 신호 | 답이 "반만" 맞음. 숫자·조건이 빠짐. 표 질문에서 머리글 없는 값이 나옴 |

## 시나리오 ②′ — 불완전 답변: 두 조각이 다 들어왔는데 하나만 쓴다

위 "고치기"를 실행하면 ②가 다른 얼굴로 다시 나타납니다.

**작성 환경의 실제 결과:** `--top-k 3`으로 #16(0.71)·#15(0.69)·#14(0.63)가 **모두** 들어왔는데도 답은 "관리자(팀장 이상)는 최대
10일 [2]"로 같았습니다. 게다가 "최대 10일"은 [1](#16)에 있고 [2](#15)는 기한 문장입니다 — **내용은 반만 쓰고 인용 번호도 어긋났습니다.**
튜토리얼 첫 질문(top-k 3에서는 기한만, top-k 8에서는 한도까지)과 같은 현상입니다. `[실행 검증 · 2026-08-30]`

**판정 규칙으로 보면:** 근거에 정답 있음 · 답 ↔ 원문 일치 · **답이 근거를 다 쓰지 않음** → 불완전 답변. 근거 목록과 인용 번호만
보면 정상으로 분류되기 때문에 세 번째 축이 필요합니다. 두 조각이 있어도 모델이 하나만 쓰는 것은 **생성 쪽 약점이지만,** 처방은
청킹에 있습니다 — 처음부터 한 조각(절 전체)으로 넣으면 모델이 고를 여지가 없습니다.

> 🔧 **한 단계 더 — 부모-자식 청킹을 직접 넣기**
>
> `load_chunks()`에서 각 조각에 `parent: 절 전체 텍스트`를 함께 저장하고, `answer()`에 넘길 때 `text` 대신 `parent`를 쓰면
> 됩니다. 검색은 작은 조각으로, 생성은 절 전체로 — 단, 같은 절의 조각 두 개가 검색되면 부모를 중복 제거해야 합니다.

| 원인 부품 | 생성 (모델이 근거를 선택적으로 읽음) — 예방은 청킹 |
| --- | --- |
| 처방 | 부모-자식 청킹, 질문에 "관련 조건을 모두 포함하라" 추가, 더 큰 모델 |
| 실무에서의 신호 | 근거 목록은 완벽한데 답에 조건·예외·한도가 빠짐. 사용자가 "그거 말고 다른 건?"이라고 되물음 |

## 시나리오 ③ — 관련 없는 문서: 답이 없는데 조각은 들어온다

**재현:** 문서에 없는 주제를 묻습니다. 점수 하한이 없는 top-k 검색은 문서가 비어 있지 않다면 가장 가까운 조각을 반환합니다.
관련성이 충분하다는 뜻은 아닙니다.

```bash
python3 rag_minimal.py "점심 식대는 얼마까지 지원되나요?" --top-k 3
```

**관찰:** 근거 목록을 보세요. 점수가 낮은(예: 0.3~0.5) 조각 — 아마 보안-정책이나 회의실 수칙 — 이 들어와 있습니다.
모델이 규칙을 잘 따르면 "문서에서 찾지 못했습니다"라고 답하지만, 소형 모델은 그 조각을 억지로 엮어 답하기도 합니다.
이때 답이 그럴듯해도 **근거 조각에 식대 얘기가 없으므로** 판정은 실패입니다.

**작성 환경의 실제 결과:** 모델이 규칙을 지켜 "문서에서 찾지 못했습니다"라고 답했습니다(근거 0.50·0.45·0.44). `[실행 검증 · 2026-08-30]`

**고치기:** 점수 하한을 둡니다. 튜토리얼 🔧에서 본 점수 분포를 참고해 정답 조각과 무관 조각 사이 값을 고릅니다.

```bash
python3 rag_minimal.py "점심 식대는 얼마까지 지원되나요?" --top-k 3 --threshold 0.55
python3 rag_minimal.py "연차는 며칠까지 이월할 수 있나요?" --top-k 3 --threshold 0.55
```

**★ 판정:** 첫 명령이 `관련 문서를 찾지 못했습니다. (점수 하한 미달 — 모델을 호출하지 않음)`을 출력하고, 두 번째(정상 질문)가
**같은 하한으로** 여전히 답하면 고쳐진 것입니다 — 하한은 양쪽을 모두 통과해야 합니다. 작성 환경에서 0.55는 식대(최고 0.50)를
차단하고 연차 이월(0.72)을 통과시켰습니다. 그러나 같은 0.55가 ①의 정답 조각(EQ-2291, 0.52)은 **막아 버립니다** — 하한 하나로 모든
질문을 만족시킬 값이 없다는 것을 [04 골든셋](04-golden-set.md)에서 숫자로 확인합니다. `[실행 검증 · 2026-08-30]`

| 원인 부품 | 검색 (하한 부재) + 데이터 (문서에 없음) |
| --- | --- |
| 처방 | 점수 하한, 하한 미달 시 모델을 부르지 않음 — [가이드 05 §3](../../guides/local-rag/05-chunking-and-retrieval-quality.md); 자주 묻는데 없는 주제는 문서 추가 |
| 실무에서의 신호 | "없는 것"을 물었을 때 엉뚱한 규정을 근거로 답함 |

## 시나리오 ③′ — 단어 겹침: 하한을 통과한 무관 조각이 환각을 부른다

**재현:** 같은 구조의 더 교묘한 경우 — 단어는 겹치는데 답은 없는 질문입니다.

```bash
python3 rag_minimal.py "연차 교육은 몇 시간 받아야 하나요?" --top-k 3
python3 rag_minimal.py "연차 교육은 몇 시간 받아야 하나요?" --top-k 3 --threshold 0.55
```

보안-정책 §3("연 1회 보안 교육… 연차 신청 시스템")이 "연차"·"교육" 두 단어로 끌려 들어옵니다.

**작성 환경의 실제 결과:** 모델이 **"연차 교육은 연 1회입니다 [1]"이라고** 답했습니다 — [1]은 보안 교육 조각(0.61)이고, "연차
교육"이라는 것은 어디에도 없습니다. 무관한 조각이 들어오자 모델이 **두 단어를 이어 붙여 없는 사실을 만든** 것입니다. 그리고
하한 0.55를 걸어도 **0.61은 통과했습니다** — 답은 그대로였습니다. `[실행 검증 · 2026-08-30]`

이것이 이 실습에서 가장 교육적인 실패입니다. ③(무관 조각 유입)이 ④(근거 없는 답변)를 부른 장면이고, 하한은 "전혀 무관한 것"만
거르지 "단어가 겹치는 무관한 것"은 거르지 못합니다. 남은 구멍은 생성 쪽에서 막아야 합니다 — [02](02-generation-failure.md).

| 원인 부품 | 검색(단어 겹침이 점수를 올림) → 생성(모델이 이어 붙임) |
| --- | --- |
| 처방 | 프롬프트에 "질문의 단어가 근거에 있어도 **같은 주제인지** 확인하라" 추가, reranker(질문·조각 쌍을 함께 읽음), 더 큰 모델 |
| 실무에서의 신호 | 용어가 비슷한 다른 규정을 근거로 자신 있게 답함. 근거 번호까지 달려 있어 사람도 속기 쉬움 |
