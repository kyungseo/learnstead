# 04 — 골든셋으로 숫자 만들기: 검색 성공률과 점수 하한의 틈

01~03에서 한 판정은 전부 눈으로 했습니다. 이 문서는 그 판정을 **반복 가능한 숫자로** 바꿉니다 — 질문 20개와 정답을 적어 두고, 검색만
20번 돌려 정답이 top-k에 들어왔는지 셉니다. 모델(생성)은 부르지 않으므로 1~2초면 끝나고, 설정을 바꿀 때마다 다시 잴 수 있습니다.

> **검증 상태:** 아래 네 설정을 Apple M4 Pro·24GB Mac, Ollama 0.33.0, `bge-m3`에서 실행했습니다. `[실행 검증 · 2026-08-30]`
> 결과는 예상과 달랐습니다 — 청킹을 바꿔도 recall이 떨어지지 않았고, 대신 **점수 하한이 들어갈 틈이 없다는 것이** 드러났습니다.

---

## 1. 골든셋 — 무엇을 적어 두나

`labs/goldenset.json`에 질문 20개가 있습니다. 15개는 답이 문서에 있고, 5개는 **문서에 없는 질문입니다**.

```json
{"q": "관리자는 연차를 최대 며칠 이월할 수 있나요?", "gold": [15, 16], "must": ["3월 말", "10일"]},
{"q": "점심 식대는 얼마까지 지원되나요?",           "gold": [],       "must": []}
```

| 필드 | 뜻 |
| --- | --- |
| `gold` | 단락 청킹 기준 정답 조각 번호(`rag_minimal.py --show`의 #). 참고용 |
| `must` | 정답에 꼭 있어야 하는 구절. **판정은 이것으로 합니다** — top-k 조각의 본문을 합쳤을 때 `must`가 모두 들어 있으면 hit |

조각 번호가 아니라 구절로 판정하는 이유는 청킹을 바꾸면 번호가 전부 달라지기 때문입니다. 구절로 재면 60자 고정 청킹과 단락 청킹을
같은 자로 비교할 수 있습니다. `[해석]` 질문 20개를 고를 때는 01~03에서 본 실패 유형을 하나씩 넣습니다 — 식별자 질문(EQ-2291),
두 조각에 걸친 질문(관리자 이월), 단어가 겹치는 없는 질문(연차 교육).

## 2. 재기

```bash
cd labs
python3 recall.py                      # dense · top-k 3 · 단락 청킹
python3 recall.py --search hybrid
python3 recall.py --top-k 5
python3 recall.py --chunk fixed:60
```

**★ 성공 판정:** 질문마다 `[O]`/`[X]`/`[없음]`이 찍히고 마지막에 필수 구절을 모두 찾은 질문의 비율인
`question success@k`와, 전체 필수 구절 중 찾은 비율인 `phrase recall@k`가 나옵니다. 이어서 정답 구절을 포함하는 조각의
최저 점수와 문서에 없는 질문 5건의 상위 점수가 출력됩니다.

작성 환경의 실제 결과: `[실행 검증 · 2026-08-30]`

| 설정 | 질문 성공률 (`question success@k`) | 필수 구절 재현율 (`phrase recall@k`) | 정답 구절 조각의 최저 dense | 없는 질문의 최고 dense |
| --- | --- | --- | --- | --- |
| dense · top-k 3 · 단락 | **15/15** | **16/16** | 0.52 (EQ-2291) | 0.61 (연차 교육) |
| hybrid · top-k 3 · 단락 | 15/15 | 16/16 | 0.52 | 0.61 |
| dense · top-k 5 · 단락 | 15/15 | 16/16 | 0.52 | 0.61 |
| dense · top-k 3 · **60자 고정** | 15/15 | 16/16 | 0.57 | 0.61 |

## 3. 읽는 법 — 두 가지가 예상과 달랐다

**첫째, 두 검색 지표가 포화됐습니다.** 조각 17개(60자 고정은 32개)짜리 문서 묶음에서는 어떤 설정이든 모든 필수 구절이 top-3에
들어옵니다. 02에서 본 "반만 맞는 답"도 검색 지표로는 잡히지 않습니다 — 두 조각이 top-3에 **들어오긴** 했으니까요(②′는 생성 쪽
문제입니다). 이 규모에서 지표가 설정을 구분하지 못한다는 것은 **문항이 너무 쉽거나 문서가 너무 작다는 신호입니다**. 실무에서는
문서가 늘고 까다로운 질문이 섞이면서 차이가 드러나며, 그때부터 같은 지표가 설정을 가릅니다. `[해석]`

**둘째, 점수 하한이 들어갈 틈이 없습니다.** 하한은 "없는 질문의 최고 점수"보다 높고 "정답 조각의 최저 점수"보다 낮아야 하는데,
작성 환경에서는 **0.61 > 0.52로 뒤집혀** 있습니다. 01 ③에서 쓴 하한 0.55는 식대(0.50)는 막지만 연차 교육(0.61)은 못 막고, **EQ-2291의
정답 조각(0.52)까지 막습니다.** 실제로 `--threshold 0.55`로 EQ-2291을 물으면 "관련 문서를 찾지 못했습니다"가 나옵니다.
`[실행 검증 · 2026-08-30]` 하한 하나로 ①과 ③′을 동시에 만족시킬 값은 이 데이터에 존재하지 않습니다. 그래서 처방이 갈립니다 —
식별자 질문은 hybrid로 점수 체계를 바꾸고, 단어 겹침은 reranker나 프롬프트로 생성 쪽에서 막습니다.

```bash
python3 rag_minimal.py "EQ-2291 장비는 어떻게 처리되나요?" --top-k 3 --threshold 0.55   # 하한이 정답을 막는 장면
```

## 4. 이 숫자를 어디에 쓰나

- **바꾸기 전과 후를 같은 자로 잰다.** 청킹·top-k·hybrid·임베딩 모델을 하나 바꿀 때마다 `recall.py`를 돌리고 [RAG 구성 카드](../../guides/local-rag/RAG-CARD.md)의
  Prove 칸에 적습니다. 숫자가 같으면 "이 규모에서는 차이가 없다"는 것도 결과입니다.
- **문항을 어렵게 만든다.** recall이 1.00이면 틀리는 질문을 찾아 추가합니다 — 표현을 바꾼 질문, 두 문서에 걸친 질문, 부정형 질문.
  골든셋은 한 번 만들고 끝이 아니라 실패가 생길 때마다 자랍니다.
- **검색과 생성을 따로 잰다.** 질문 성공률과 필수 구절 재현율은 검색만 봅니다. 답이 근거에 충실한지(faithfulness)는 사람이 채점하거나 다른 모델에게 묻는
  별도의 층이며, 그 확장은 [가이드 09 §4](../../guides/local-rag/09-personal-vs-enterprise.md)와 별도 평가 가이드에서 다룹니다.

## 5. 초기화

`recall.py`는 파일을 만들지 않습니다. 골든셋을 고쳤다면 `git diff labs/goldenset.json`으로 무엇을 바꿨는지 남겨 두세요.
