# 01 — 단계별로 만들기: 색인 → 검색 → 근거 있는 답변

`rag_skeleton.py` 한 파일로 가상 규정 4편에 답하는 RAG를 만들고, 답이 나올 때마다 **근거가 답을 뒷받침하는지** 판정합니다.

← [README](README.md) · 다음 → [02 저장소를 Chroma로 바꾸기](02-chroma.md)

> **검증 상태:** 이 문서의 모든 명령을 Apple M4 Pro·24GB Mac, Ollama 0.33.0, `bge-m3`·`gemma3:4b`에서 실행했습니다.
> `[실행 검증 · 2026-08-30]` "실제 출력"은 그때 관찰한 것이며, 점수와 답의 표현은 모델·버전에 따라 달라집니다.

---

## 1. 파일 배치

이 자료의 `labs/` 디렉터리를 통째로 복사합니다.

```text
labs/
├── docs/
│   ├── 휴가-규정.md      # 연차 발생·신청·이월·경조 휴가
│   ├── 장비-규정.md      # 지급·반납·분실·교체 (자산 코드 EQ-2291 포함)
│   ├── 회의실-예약.md    # 종류·예약·노쇼·수칙
│   └── 보안-정책.md      # 비밀번호·저장 매체·교육·신고
├── rag_skeleton.py       # 이 문서의 본문 — 핵심 함수 다섯 개
└── rag_chroma.py         # 02 선택 단계
```

예제 문서는 **가상의 회사 규정입니다.** 실습에서 실패를 재현하기 쉽도록 일부러 넣은 장치가 있는데, 지금은 몰라도 됩니다
(휴가-규정 §3의 "이월 한도" 목록이 앞 문장과 **다른 단락에** 있다는 것만 §2에서 확인해 두세요). `[해석]`

## 2. 스크립트 읽기 — 파이프라인이 코드에서 보이는가

`rag_skeleton.py`는 핵심 함수 다섯 개, 60줄 남짓입니다(CLI와 주석을 합쳐 100줄). 실행 전에 다음 다섯 곳을 찾아보세요. 괄호의
번호는 [가이드 03](../../guides/local-rag/03-pipeline-anatomy.md)의 파이프라인 단계입니다.

| 단계 | 함수 | 확인할 것 |
| --- | --- | --- |
| (1)(2) 파싱·청킹 | `load_chunks()` | 단락(`\n\n`) 단위로 자르고, 조각 앞에 `[파일 › 절]` 출처를 붙인다 |
| (3)(5) 임베딩 | `embed()`, `cosine()` | 색인과 질의가 **같은 함수·같은 모델을** 쓴다 |
| (6) 검색 | `search()` | 질문 벡터와 모든 조각 벡터의 코사인 유사도를 재고 상위 k개를 고른다 |
| (7) 프롬프트 조립 | `answer()`의 `RULES`·`evidence` | "근거만·없으면 모른다·번호 인용" 세 규칙 → 번호 붙인 근거 → 질문 |
| (8) 생성 | `answer()`의 `chat.completions.create` | `temperature=0` |

vector store가 없다는 점에 주목하세요. 조각 17개를 리스트에 들고 매번 전부 비교합니다. 이것이 **RAG의 최소 동작 구조이며,**
나머지는 규모·품질·운영을 위해 더하는 부품입니다. `[원리]`

### 조각 목록 보기

```bash
cd labs
python3 rag_skeleton.py --show
```

**★ 성공 판정:** 조각 17개가 `#번호 파일 › 절 (글자 수)` 형식으로 출력됩니다. 이 단계는 모델을 호출하지 않으므로 Ollama가
없어도 동작합니다. `[실행 검증 · 2026-08-30]`

휴가-규정 §3이 **두 조각(#15, #16)으로** 나뉜 것을 눈여겨 두세요. §3에서 바로 다시 만납니다.

## 3. 첫 질문

```bash
python3 rag_skeleton.py "연차는 며칠까지 이월할 수 있나요?"
```

작성 환경에서 관찰한 실제 출력(첫 호출 약 8초 — 모델을 메모리에 올리는 시간 포함, 이후 1~3초):

```text
답변: 다음 해 3월 말까지 이월해 사용할 수 있습니다 [1].

근거:
 [1] #15 휴가-규정 › 3. 연차 이월  (score 0.72)
 [2] #16 휴가-규정 › 3. 연차 이월  (score 0.72)
 [3] #14 휴가-규정 › 2. 연차 신청  (score 0.67)

판정 힌트: 답에 인용된 번호의 조각 안에 그 내용이 실제로 있는가?
```

**★ 성공 판정:**

1. 오류 없이 `답변:`과 `근거:`가 출력된다.
2. 근거 상위에 `휴가-규정 › 3. 연차 이월`이 있다.
3. 답에 인용 번호가 붙어 있고, 그 번호의 조각(`--show`로 확인)에 "3월 말"이 **실제로 있다.**

3번이 판정의 핵심입니다. 답의 문장이 매끄러운지는 보지 않습니다. 점수 값과 답의 표현은 모델·버전에 따라 달라지므로 위 출력과
글자 단위로 같을 필요는 없습니다. `[실행 검증 · 2026-08-30]`

### 맞았지만 반만 답했다

위 답은 맞습니다. 그런데 **"며칠까지"를** 기한으로만 읽고, [2]에 있는 한도(5일·10일)는 쓰지 않았습니다. 같은 질문을 `--top-k 8`로
실행하자 답이 바뀌었습니다. `[실행 검증 · 2026-08-30]`

```bash
python3 rag_skeleton.py "연차는 며칠까지 이월할 수 있나요?" --top-k 8
```

```text
답변: 다음 해 3월 말까지 이월해 사용할 수 있습니다 [1]. 이월 한도는 직급에 따라 다르며, 일반 직원은 최대 5일,
관리자(팀장 이상)는 최대 10일입니다 [2].
```

근거 [1]·[2]는 top-k 3일 때와 같았는데 답이 달라졌습니다. 이런 **"근거는 맞는데 덜 쓴 답"이** 어디서 오고 어떻게 판정하는지는
[실습 ②′](../../labs/why-rag-fails/01-retrieval-failures.md)에서 다룹니다. 지금은 "근거 목록만 보고 안심하면 안 된다"는 것만
기억해 두세요.

### 실패했을 때

| 증상 | 확인 |
| --- | --- |
| `Connection refused` | Ollama가 떠 있는가 (`curl http://localhost:11434/`) |
| `model "bge-m3" not found` | `ollama pull bge-m3` 실행 여부, `ollama list` |
| 근거는 맞는데 답이 근거와 다름 | 모델이 규칙을 어긴 것 — [실습 ④](../../labs/why-rag-fails/02-generation-failure.md), 또는 더 큰 모델로 교체 |
| 근거에 엉뚱한 조각만 있음 | 질문을 바꿔 보고, 그래도 그러면 [실습 ①](../../labs/why-rag-fails/01-retrieval-failures.md)의 hybrid |

## 4. 질문 몇 개 더

각각 실행하고 **근거 판정을** 반복합니다.

```bash
python3 rag_skeleton.py "노트북은 언제까지 반납해야 하나요?"
python3 rag_skeleton.py "회의실은 한 번에 몇 시간까지 쓸 수 있어요?"
python3 rag_skeleton.py "비밀번호 바꾸는 주기가 어떻게 되죠?"
```

질문의 표현이 문서와 다르다는 점("바꾸는 주기" ↔ "90일마다 변경")에 주목하세요. 이것이 dense 검색이 하는 일입니다.
작성 환경에서 세 질문 모두 정답 조각이 1위 또는 2위로 검색됐고(0.63~0.70) 답이 근거와 일치했습니다. 노트북 질문은 1위가
`교체 주기`(0.67), 정답인 `장비 반납`이 2위(0.63)였는데 모델이 [2]를 정확히 인용했습니다 — 1위가 항상 정답은 아니고, 그래서
top-k가 1보다 커야 합니다. `[실행 검증 · 2026-08-30]`

> 🔧 **한 단계 더 — 점수 감각 잡기**
>
> 같은 질문을 `--top-k 8`로 실행해 8개 조각의 점수를 쭉 보세요. 작성 환경의 연차 이월 질문에서는 정답 조각(0.72·0.72) 다음에
> 같은 파일의 다른 절(0.67·0.66), 그 다음 무관한 조각(0.53 이하)이 이어졌습니다. 정답과 무관한 조각 사이에 보이는 간격이 내
> 데이터의 **점수 하한** 후보입니다. [실습 ③](../../labs/why-rag-fails/01-retrieval-failures.md)에서 씁니다.

## 5. 기록하기

이 시점의 구성을 [RAG 구성 카드](../../guides/local-rag/RAG-CARD.md)에 적어 두면, 실습에서 무엇을 바꿨을 때 무엇이 달라졌는지 비교할
수 있습니다.

```text
Index: docs 4편 · 단락 청킹 · 조각 17개 · bge-m3 (1024d) · 리스트
Ask:   dense · top-k 3 · threshold 없음 · 규칙 3종 · gemma3:4b · temperature 0
Prove: 질문 4건 · 근거 판정 통과 4건 / 실패 0건 (첫 질문은 top-k 3에서 한도 생략)
```
