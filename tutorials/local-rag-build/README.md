# 내 문서에 답하는 Local RAG 만들기

![문서 폴더와 노트북의 로컬 모델에서 조각·벡터·검색을 거쳐 근거 번호가 붙은 답을 만드는 손그림](assets/local-rag-build-hero.webp)

가상의 사내 규정 4편을 대상으로 **검색 → 프롬프트 조립 → 근거를 포함한 답변까지** 한 경로로 완성하는 튜토리얼입니다. 외부 서비스
없이 Ollama와 Python 한 파일만 씁니다. 벡터 데이터베이스도 프레임워크도 없이 **임베딩 + 리스트 + 코사인 유사도 + 근거 규칙만으로**
RAG가 된다는 것, 그리고 답이 나왔을 때 **근거가 답을 정말 뒷받침하는지** 판정하는 습관이 이 튜토리얼의 결과물입니다.

이 자료는 세 편으로 이어지는 시리즈의 두 번째입니다. 원리는 [가이드: 내 문서와 대화하는 AI 이해하기](../../guides/local-rag/README.md), 완성한
스크립트로 실패를 일부러 만들어 보는 일은 [실습: RAG는 왜 틀리는가](../../labs/why-rag-fails/README.md)가 맡습니다. 가이드를 읽지 않았어도 이
튜토리얼은 그대로 따라 할 수 있습니다.

> **검증 상태:** 아래 전체 경로(색인 → 검색 → 생성, 선택 단계인 Chroma 포함)를 Apple M4 Pro·24GB Mac, Ollama 0.33.0,
> `bge-m3`·`gemma3:4b`에서 실제로 실행했습니다. `[실행 검증 · 2026-08-30]` 본문의 "실제 출력"은 그때 관찰한 출력입니다.
> 모델·버전이 다르면 답의 표현과 점수가 달라지므로 각 단계의 성공 판정 기준으로 확인하세요. 상세는 [검증 기록](VALIDATION.md).

**[준비 확인 → 아래 §지원 환경](#지원-환경과-사전-준비)** · **[바로 시작 → 01 단계별로 만들기](01-build.md)**

## 학습 달성 목표(Learning Objective) — 이 튜토리얼을 끝내면 할 수 있는 것

- `rag_skeleton.py`의 다섯 함수가 RAG 파이프라인의 어느 단계인지 가리킬 수 있습니다.
- 내 질문에 대해 **어느 문서의 어느 조각을 근거로 썼는지가** 함께 출력되는 답을 받을 수 있습니다.
- 답의 문장이 매끄러운지가 아니라 **인용된 조각 안에 그 내용이 실제로 있는지로** 성공을 판정할 수 있습니다.
- 저장소를 Python 리스트에서 파일 기반 vector store(Chroma)로 바꿔도 임베딩·프롬프트·생성은 그대로라는 것을 확인할 수 있습니다.

## 지원 환경과 사전 준비

| 항목 | 요구 사항 | 확인 방법 |
| --- | --- | --- |
| Ollama | 실행 중 (버전 0.33.0에서 확인) | `curl http://localhost:11434/` → `Ollama is running` |
| 모델 | `bge-m3`(임베딩), `gemma3:4b`(대화) | `ollama pull bge-m3`, `ollama pull gemma3:4b` 후 `ollama list` |
| Python | 3.10 이상 (3.14에서 확인) | `python3 --version` |
| 패키지 | `openai` (02 선택 단계는 `chromadb` 추가) | `pip install openai` |
| 디스크 | 모델 두 개 약 4.5GB | — |
| 메모리 | 통합 메모리 또는 GPU 8GB 이상 권장 (24GB에서 확인) | — |

`[문서 확인 · 2026-08-30]` 모델 태그는 Ollama library에서, 패키지는 PyPI에서 확인할 수 있습니다. 모델을 띄우는 방법 자체가 처음이라면
[내 장비에서 LLM 직접 실행하기](../../guides/local-llm/README.md)를 먼저 보세요.

> 대화 모델은 Ollama library의 다른 모델로 바꿔도 됩니다. 단 **임베딩 모델은 색인과 질의에서 같아야** 하므로 스크립트 상단의
> `EMBED_MODEL`만 바꾸고, 바꿨다면 색인을 다시 합니다. `[원리]`

## 가장 짧은 경로 — 네 단계

1. 이 자료의 `labs/` 디렉터리를 통째로 복사합니다(가상 규정 4편 + 스크립트 2개).
2. `python3 rag_skeleton.py --show`로 문서가 **조각 17개로** 잘린 것을 봅니다. 모델을 부르지 않으므로 Ollama 없이도 됩니다.
3. `python3 rag_skeleton.py "연차는 며칠까지 이월할 수 있나요?"`를 실행합니다.
4. 답변 아래에 **어느 조각을 근거로 썼는지가** 점수와 함께 나오고, 그 조각 안에 "3월 말"이 실제로 있으면 첫 성공입니다.

단계별 예상 출력과 성공 판정, 실패했을 때 볼 곳은 [01 단계별로 만들기](01-build.md)에 있습니다.

## 흔한 실패와 원상복구

| 증상 | 확인할 것 |
| --- | --- |
| `Connection refused` | Ollama가 떠 있는가 (`curl http://localhost:11434/`) |
| `model "bge-m3" not found` | `ollama pull bge-m3` 실행 여부, `ollama list` |
| `ModuleNotFoundError: openai` | 같은 Python 환경에 `pip install openai`를 했는가 (`python3 -m pip install openai`) |
| 첫 질문이 10초 넘게 걸림 | 첫 호출은 모델을 메모리에 올리는 시간이 포함됩니다(작성 환경 8초, 이후 1~3초) |
| 근거는 맞는데 답이 근거와 다름 | 모델이 규칙을 어긴 것 — [실습 ④](../../labs/why-rag-fails/02-generation-failure.md) |
| 근거에 엉뚱한 조각만 있음 | 질문을 바꿔 보고, 그래도 그러면 [실습 ①·③](../../labs/why-rag-fails/01-retrieval-failures.md) |

**원상복구:** 01은 파일을 만들지 않습니다(리스트 기반이라 매 실행 시 다시 색인). 02를 했다면 `python3 rag_chroma.py --reset`으로
`chroma_db/`를 지웁니다. 모델을 내리려면 `ollama stop gemma3:4b`.

## 범위

이 튜토리얼이 끝나는 지점은 **가상 규정 4편에 대해 로컬 모델이 근거를 제시하며 답하고, 그 근거가 답을 뒷받침하는지 내가 판정한
순간입니다.** 다음은 다루지 않습니다.

- 키워드 검색(BM25)·hybrid·reranker·점수 하한 — 실습에서 실패를 재현하며 다룹니다
- PDF·HWP 파싱, 수천 개 이상 조각의 색인, 권한·갱신·운영
- 프레임워크(LangChain·LlamaIndex 등)로 같은 일을 하는 방법
