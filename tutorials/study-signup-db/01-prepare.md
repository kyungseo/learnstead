# 01. 준비 — 내 컴퓨터 안에 연습용 DB 띄우기

[← 목차](README.md) · [전체 목차](README.md) · [02 구조 →](02-model.md)

이 단계의 결과는 **내 컴퓨터에서만 사용하는 연습용 DB가 준비된 상태입니다.** 아직 신청 버튼을 만들지 않습니다. 먼저 명령을 어디에서 실행하는지, 데이터가 어디에 생기는지 확인합니다.

## 준비할 것

| 준비물 | 맡는 일 | 확인 |
| --- | --- | --- |
| [Docker Desktop](https://docs.docker.com/desktop/) | 내 컴퓨터에서 DB와 인증 서비스를 실행 | Docker Desktop이 실행 중이며 `docker info`가 성공 |
| [Node.js 24 LTS와 npm](https://nodejs.org/en/download) | 앱·설정 스크립트 실행 | `node --version`, `npm --version` |
| Learnstead 전체 파일 | 앱, DB 구조, 실습 코드의 상대 경로 유지 | 저장소를 내려받거나 복제 |
| 웹 브라우저 | 완성할 앱 사용 | 브라우저에서 로컬 주소 열기 |

터미널이 처음이라면 [Git 환경 준비](https://github.com/kyungseo/learnstead/blob/main/guides/git-for-vibe-coders/03-setup-mac-windows.md)에서 폴더 이동과 명령 실행부터 익혀도 됩니다. 이 자료에서는 macOS 터미널의 명령을 기준으로 설명합니다. 실제 확인한 버전은 [검증 기록](VALIDATION.md)에 있습니다. 로컬 시작 도구는 Unix 소켓으로 연결하는 Docker 환경을 대상으로 하며, 이 자료의 기준은 macOS의 Docker Desktop입니다. Windows 네이티브 Docker 소켓·원격 Docker에는 이 명령 경로를 그대로 적용하지 않습니다. Windows·Linux·클라우드 배포는 이 경로의 실행 검증에 포함하지 않습니다.

Supabase CLI는 로컬 서비스를 실행할 때 Docker와 호환되는 실행 환경을 사용합니다. 이 자료에는 설정 파일이 포함되어 있으므로 별도로 `supabase init`을 실행해 덮어쓸 필요가 없습니다. `[문서 확인 · 2026-09-13]` [공식 로컬 개발 안내](https://supabase.com/docs/guides/local-development)

## 실습 데이터의 경계

새 연습 폴더에서 시작하고 가상 사용자만 사용하세요. 이 자료의 초기화·검증 명령은 연습 데이터를 다시 만들거나 지웁니다. 직접 보존해야 할 신청 내역을 이 DB에 넣지 않습니다.

클라우드 프로젝트 생성이나 연결은 필요 없습니다. 실제 서비스의 DB 주소·관리자 키를 복사해 넣지 마세요. 로컬 스크립트가 사용하는 연결 대상과 프로젝트 식별자를 확인한 뒤 실행합니다. 이름이 비슷하다는 사실만으로 현재 DB가 연습용이라고 판단하지 않습니다.

## 설치하고 시작하기

Learnstead 전체를 내려받은 **저장소 최상위 폴더**에서 실행합니다. `cd`는 명령을 실행할 폴더를 옮깁니다. 아래에서는 앱의 `package.json`이 있는 폴더로 이동합니다.

```bash
cd tutorials/study-signup-db/app
npm ci
npm run db:start
npm run setup
```

`npm ci`는 잠금 파일에 기록한 패키지 버전을 설치합니다. 이 자료의 Supabase CLI도 함께 설치하므로 별도 전역 CLI는 필요 없습니다. `db:start`는 프로젝트의 로컬 DB·인증·API를 시작하고, `setup`은 가상 계정과 브라우저용 공개 설정을 만듭니다.

| 명령이 끝난 지점 | 기대 결과 |
| --- | --- |
| `npm ci` | 패키지 설치가 오류 없이 완료 |
| `npm run db:start` | `PASS 로컬 Supabase 시작`, API·Studio 주소 안내 |
| `npm run setup` | `PASS 연습 계정 2개 준비`, 공개 설정 생성 안내 |

이 앱의 주소는 [웹 화면](http://127.0.0.1:5173), API는 `http://127.0.0.1:55321`, [DB 관리 화면 Studio](http://127.0.0.1:55323)입니다. DB 포트는 `55322`입니다. `127.0.0.1`은 지금 사용하는 컴퓨터 자신을 가리킵니다. 관리 화면은 테이블을 직접 볼 수 있는 높은 권한의 도구이므로 일반 사용자 권한 확인에는 사용하지 않습니다.

최초 시작의 기준 데이터는 **모임 3개, 신청 0개**입니다. 다음 단계에서 앱에 로그인해 확인합니다. `setup`을 다시 실행해도 기존 신청은 지워지지 않습니다. 이전 실습 데이터가 있는 상태에서 모임·신청을 기준 상태로 바꾸려면 아래의 명시적 초기화가 필요합니다.

## 처음부터 다시 시작하려면

다음 명령은 **이 연습 DB의 계정·신청 데이터를 삭제하고** 모임 세 개·신청 0개 상태를 다시 만듭니다. 보관할 연습 결과를 먼저 기록하세요. 데이터가 남는지 시험하는 도중에는 초기화하지 않습니다.

```bash
npm run db:reset -- --confirm-local-reset
```

이 명령은 연습용 서비스를 멈추고 이 프로젝트 소유의 DB 볼륨 하나를 새로 만든 뒤 다시 시작합니다. SQLite 파일과 `app/.local`의 백업·검증 기록은 지우지 않습니다.

성공하면 `연습 DB 초기화 완료: 이벤트 3개, 신청 0개`가 출력됩니다. 앱에 로그인 중이었다면 새로고침하고 다시 로그인합니다. 이 프로젝트가 이미 실행 중이어야 하며, 중지 상태라면 먼저 `npm run db:start`를 실행합니다.

## 파일에서 찾아볼 세 곳

| 위치 | 읽을 때 던질 질문 |
| --- | --- |
| `supabase/config.toml` | 어떤 로컬 프로젝트와 포트를 사용하는가? |
| `supabase/migrations/` | 어떤 테이블과 접근 규칙을 만드는가? |
| `app/` | 화면이 어디로 데이터를 요청하는가? |

**폴더에 보이는 소스 파일과 DB 안에 저장되는 신청 내역은 별개입니다.** 소스를 Git으로 되돌려도 DB의 행이 자동으로 되돌아오지는 않습니다. DB 데이터는 Docker가 관리하는 저장 공간에 남습니다.

## 처음 실행할 때 오래 걸리면

처음에는 DB와 인증 서비스를 실행할 이미지 파일을 내려받습니다. 인터넷 연결과 여유 디스크가 필요하고, 이미지를 보유한 다음 실행보다 오래 걸릴 수 있습니다. 진행 로그가 계속 늘면 다운로드와 시작 과정일 수 있습니다. 오류로 끝났다면 마지막 오류 문구를 먼저 읽으세요.

| 증상 | 먼저 확인할 것 |
| --- | --- |
| `node` 또는 `npm`을 찾지 못함 | Node.js 설치 후 터미널을 다시 열었는가? |
| Docker 연결 오류 | Docker Desktop이 준비를 끝냈는가? |
| 포트를 이미 사용한다는 오류 | 다른 로컬 Supabase 프로젝트가 실행 중인가? |
| 이미지 다운로드 실패 | 인터넷·디스크 상태와 Docker 오류 로그 |
| 앱 명령이 파일을 찾지 못함 | 터미널의 현재 폴더가 이 튜토리얼의 `app`인가? |

실행 도구가 실패하며 남긴 `app/.local/cli-failure.log`에는 로컬 관리자 키가 포함될 수 있습니다. 이 파일을 그대로 게시하거나 AI에게 첨부하지 말고, 키·토큰을 제거한 오류 부분만 공유하세요.

오류를 없애려고 컴퓨터의 모든 Docker 컨테이너나 볼륨을 지우지 마세요. 이 자료의 프로젝트만 확인하고 멈추면 됩니다. 다른 작업의 DB도 Docker에서 실행 중일 수 있습니다.

## AI와 함께 확인하기

> “이 튜토리얼의 로컬 설정을 읽고, 사용할 프로젝트 이름·주소·포트와 데이터를 다시 만드는 명령을 설명해 줘. 클라우드 연결은 추가하지 말고, 다른 Docker 프로젝트를 변경하지 마. 먼저 실행 환경이 준비됐는지 확인해 줘.”

이 요청문은 AI가 따라야 할 작업 지침입니다. 실제 접근을 막아 주는 장치는 연결 대상 제한·DB 권한·격리된 연습 환경입니다. 요청문을 보냈다는 사실만으로 안전이 보장되지는 않습니다.
