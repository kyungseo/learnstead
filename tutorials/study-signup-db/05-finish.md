# 05. 완성 — 확인하고 멈추고 다시 시작하기

[← 04 권한](04-access.md) · [전체 목차](README.md) · [실습으로 →](../../labs/database-safety/README.md)

이제 내 컴퓨터에서 모임을 읽고, 로그인한 사용자가 신청하고, 다시 들어와 자기 신청을 확인하는 앱이 있습니다. 마지막으로 **완성의 근거와 다시 시작할 방법을 남깁니다.**

## 화면에서 마지막 확인

| 해 볼 일 | 기대 결과 |
| --- | --- |
| A로 신청 | A의 신청 목록에 한 건 표시 |
| 신청한 모임의 버튼 확인 | `신청 완료`로 바뀌며 중복 클릭 불가 |
| 새로고침 후 다시 읽기 | 신청이 유지됨 |
| B로 로그인 | A의 개인 신청 내역이 보이지 않음 |
| 로그아웃 | 개인 신청 내역에 접근하지 못함 |

“앱이 잘 돼요”보다 이 다섯 줄이 다음 변경 때 더 유용합니다. 일부를 확인하지 않았다면 빈칸을 성공으로 채우지 말고 확인하지 못했다고 기록하세요.

## 앱을 멈추는 것과 DB를 지우는 것

웹 서버를 실행한 터미널에서 `Ctrl+C`를 누르면 화면을 제공하던 서버가 멈춥니다. DB 서비스는 별도로 실행 중일 수 있습니다. DB를 멈추는 명령과 DB를 초기 상태로 다시 만드는 명령도 구분합니다.

- **멈추기:** 자원을 쉬게 하고 다음에 이어서 실행합니다.
- **초기화:** 연습 데이터를 버리고 기준 상태에서 다시 시작합니다.
- **복원:** 보관한 백업의 시점으로 데이터를 되살립니다.

세 작업은 목적이 다릅니다. 연습 데이터를 초기화할 수 있다는 사실은 중요한 데이터를 복원할 수 있다는 증거가 아닙니다. 실제 복원은 [실습 06](../../labs/database-safety/06-restore.md)에서 별도 대상으로 검증합니다.

## 멈추고 다시 시작하기

웹 서버를 실행한 터미널에서 `Ctrl+C`를 누릅니다. 그 뒤 같은 `app` 폴더에서 DB 서비스를 멈춥니다.

```bash
npm run db:stop
```

이 명령은 이 연습 프로젝트만 중지하며 로컬 볼륨의 데이터는 보존합니다. 다음에 다시 실행하려면 같은 폴더에서 다음 순서로 실행합니다.

```bash
npm run db:start
npm run setup
npm run dev
```

다시 [앱](http://127.0.0.1:5173)을 열고 같은 사용자로 로그인합니다. 기존 신청이 보이면 중지·재시작 뒤에도 같은 DB를 읽는 것을 확인한 것입니다. `setup`은 기존 신청을 보존합니다. 처음부터 시작할 목적이라면 별도의 [명시적 초기화](01-prepare.md)를 사용합니다.

## 내 프로젝트에 옮기기 전 남길 기록

다음 표를 복사하고 이번 앱에서 확인한 값을 채워 보세요. 실제 키나 비밀번호는 기록하지 않습니다.

| 항목 | 내 기록 |
| --- | --- |
| 앱이 저장하는 것 | 모임과 사용자별 신청 내역 |
| DB와 실행 위치 | 로컬 Supabase의 PostgreSQL |
| 사용자 구분 | Supabase Auth |
| 중복·관계 규칙 | 같은 모임 중복 신청 금지, 존재하는 모임·사용자에 연결 |
| 접근 기준 | 로그인한 사용자의 모임 조회 / 본인의 신청 |
| 변경 기록 | migration 파일 |
| 멈추고 다시 시작할 방법 | 아래 실행 절차 |
| 아직 확인하지 않은 범위 | 클라우드·실제 개인정보·운영 부하 등 |

DB가 필요한 앱을 AI에게 맡길 때도 이 표부터 작성하면 무엇을 확인해야 하는지 구체적으로 요청할 수 있습니다. 실제 운영을 앞두고는 담당자, 백업 보관·복원, 비용, 계정 관리도 정해야 합니다. [가이드](../../guides/database-for-vibe-coders/README.md)에서 선택 기준을 더 읽을 수 있습니다.

## 클라우드로 옮기는 일은 다음 작업

이 튜토리얼은 인터넷 공개 배포까지 완료했다는 뜻이 아닙니다. 클라우드 프로젝트의 설정·메일 인증·주소·비밀값·요금·백업 조건을 따로 확인해야 합니다. 로컬 계정과 예제 비밀번호를 운영 환경에 옮기지 않습니다.

Supabase는 migration을 이용해 DB 구조 변경을 관리하는 경로를 안내합니다. `[문서 확인 · 2026-09-13]` [공식 migration 문서](https://supabase.com/docs/guides/deployment/database-migrations). 해당 클라우드 경로는 이 자료에서 실행 검증하지 않았습니다.
